## 已定

1. 只走局域网（评审点 2）。不做远程通道、不做 mDNS 发现；地址由配对二维码带给手机。
2. API 开两个监听：
   - 回环 HTTP：`HOST`（默认 `127.0.0.1`）:`PORT`（默认 `8787`）。宿主、开发调试和 `/host/*` 管理接口只走这里。
   - 局域网 HTTPS：`LAN_HTTPS_HOST`（默认 `0.0.0.0`）:`LAN_HTTPS_PORT`（默认 `8788`，设 `0` 关闭）。手机只走这里。`/host/*` 不挂在这个监听上。
3. 数据目录 `CATTT_DATA_DIR`：宿主传 `~/Library/Application Support/Cattt`；不传时开发默认 `server/.local/`（已 gitignore）。API 启动时缺什么建什么：
   - `tls/ca.key`、`tls/ca.crt`：本机自签 CA（ECDSA P-256，有效 10 年），只生成一次，**换了 CA 所有手机都要重新配对**。
   - `tls/server.key`、`tls/server.crt`：CA 签发的服务端证书（有效 365 天，EKU serverAuth），SAN 含 `localhost`、`127.0.0.1`、`<主机名>.local` 和当前全部局域网 IPv4。启动时与每 60 秒检查一次：IP 变了或剩余不足 30 天就重签并热替换，不重启。
   - `host-admin.token`：管理口令（随机 32 字节 base64url，文件权限 0600）。宿主读它调用 `/host/*`。
   - 私钥文件权限 0600，目录 0700。宿主备份时包含 `tls/`，升级时不得重建。
4. CA 指纹 `fp` = CA 证书 DER 的 SHA-256，64 位小写十六进制。手机以它固定信任：TLS 握手时在服务端证书链里找到指纹相符的 CA，只以它为锚点校验（含主机名），不信任系统根证书，也不接受别的 CA。
5. 配对码：8 位 Crockford Base32（不含 I L O U），显示为 `XXXX-XXXX`，输入不分大小写、忽略连字符。10 分钟有效、一次性；同一码输错累计 5 次即作废；新签发的码不让旧码失效。库里只存哈希。
   - 实施约定：错误的码无法定位到某个已签发码，因此每次格式合法但验证失败的 `/pair` 请求，对所有仍有效、未使用的码累计一次失败；达到 5 次即烧毁。格式错误的请求返回 400，不计次数。
6. 配对链接（二维码内容即此链接，iOS 系统相机扫码可直接打开 App）：
   `maomao://pair?v=1&h=<地址1>,<地址2>&p=<LAN_HTTPS_PORT>&c=<配对码>&fp=<CA 指纹>`
   `h` 按优先顺序列出局域网 IPv4 与 `<主机名>.local`；手机依次尝试。手动配对时用户填地址与配对码，手机先展示指纹前 16 位（4 组，如 `3f2a 9c01 …`）让用户与电脑上显示的核对一致后才发送配对码。
7. 设备凭证：配对成功返回 `mm_dvc_` 开头的长期 token（随机 32 字节），手机存 Keychain（`ThisDeviceOnly`），以 `Authorization: Bearer` 调用全部 `/v1/*`。不过期，宿主撤销或手机解除配对即失效。库里只存哈希，记录设备名、配对时间、最后使用时间。
8. 一台电脑一个主人（本地优先第 4 条）：首次签发配对码时若还没有主人账号就建一个（连同团子和对话），之后所有配对设备都归这个主人。Apple 登录会话与开发者 token 暂时照旧可用，由 G 批收敛。

## 接口

宿主管理（回环 HTTP，`Authorization: Bearer <host-admin.token>`，口令不对 401）：

| 方法与路径 | 作用 | 返回 |
|---|---|---|
| `POST /host/pairing-codes` | 签发配对码 | `{code, expires_at, pair_url, hosts, port, ca_fingerprint, ca_fingerprint_short}` |
| `GET /host/devices` | 已配对设备 | `{devices:[{id, name, created_at, last_seen_at}]}`（不含已撤销） |
| `DELETE /host/devices/:id` | 撤销设备 | `{ok:true}` |
| `GET /host/status` | 宿主展示用 | `{lan:{enabled, hosts, port}, ca_fingerprint, ca_fingerprint_short, devices}` |

手机（局域网 HTTPS）：

| 方法与路径 | 鉴权 | 作用 |
|---|---|---|
| `GET /healthz` | 无 | 健康检查（与现有一致） |
| `POST /pair` `{code, device_name}` | 无（配对码） | 成功 `{device_id, device_token, account_id, cat}`；码不对/过期/作废 `401 {error:{code:'pairing_code_invalid'}}`；请求格式不对 400 |
| `POST /v1/device/unpair` | 设备 token | 撤销自己 |
| `/v1/*` | 设备 token | 与现有接口相同 |

宿主命令行备选：`pnpm --dir server pair`（直接连库签发并打印配对码、链接和终端二维码），开发与无界面时用。
