# 聊天云端、记忆本机 · 2026-11-19

## 已定

1. 支持混合来源预设，不新增或改名环境变量：`MODEL_PROVIDER=openai-compatible`、`OPENAI_COMPAT_MODEL=本机模型名`；`CHAT_PROVIDER`、`ROUTER_PROVIDER`、`WORKER_PROVIDER` 均为 `deepseek`，密钥使用 `MAOMAO_DEEPSEEK_API_KEY`。`EXTRACT_PROVIDER` 不设置，继承本机来源。
2. 聊天、事件路由和托付执行走 DeepSeek；记忆提取、边界概括、召回扩词、日记读取（`diary_read`）与猫日记生成（`cat_diary`）走 extract 槽位。每日猫日记的事件筛选（`route`）仍走 router。猫日记生成保留原调用路径的思考开关；mock 行为不变。
3. 本机与云端按实际槽位来源分开计算并发准入；本机槽位共享服务地址对应的资源。并发设为 0 表示关闭准入限制，不是关闭该来源。
4. 连通检查覆盖全部槽位使用的来源、模型与思考模式；设置本机模型不得覆盖槽位的来源与模型覆盖。配置示例见 [server/.env.example](../../server/.env.example)。
5. 这是模型调用分工，不是数据不出本机的承诺：经许可进入云端聊天、路由或托付上下文的记忆、日记相关内容仍可能发送到 DeepSeek。不改变既有许可、边界过滤和预算约束。
