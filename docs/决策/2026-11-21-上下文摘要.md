# 超预算上下文的临时摘要

前台聊天与后台托付在 56 KiB 输入预算发生裁剪时，为被丢弃的完整旧轮次或工具链生成一次模型摘要。先按原规则判断是否需要裁剪，再预留 4 KiB；当前用户问题和保留的工具调用／结果配对不拆开。必要尾部仍放不下时保持原预算错误。摘要以用户角色的数据标签插回首个被丢弃位置，不作为系统指令；与后文冲突以后文为准。

摘要输入按片段与总字节数限界，使用本次聊天／worker 槽位发起一次非流式请求，不另换供应商。输出按 Unicode 码点和序列化字节限额截断；实例内以被丢弃消息的 SHA-256 缓存，不落库。失败只记不含内容的警告并退回普通裁剪；取消和权限复核失败仍终止请求。摘要用量单独记为 `context_summary`，托付摘要输出即时计入原有 8000 token 额度。

摘要只取本次请求已经选入、已经获准的消息，不读取新来源；生命周期仅为本轮聊天或本次 worker 调用。下一轮重新构建许可上下文，因此撤回照常生效；摘要前后以及后续模型／工具操作继续复核 guard。托付检查点保存完整未摘要历史，绝不保存临时摘要。摘要不改变云端／本地分槽配置；原本获准进入 DeepSeek 的消息，其摘要也由同一槽位处理。

仅以 [Linger](https://github.com/simplexai-labs/linger) 为架构参考，不复制代码或 UI。其 [LICENSE](https://github.com/simplexai-labs/linger/blob/main/LICENSE) 为带额外托管服务与前端标识条件的修改版 Apache 2.0。后台抢占、主题记忆和 macOS 客户端不在本次范围。
