# R8.11 · Bun 宿主备份恢复

- Bun 成品的回环管理入口使用 SQLite `VACUUM INTO` 生成独立快照。备份目录含版本清单、SHA-256、大小、SQLite 迁移版本与结构、本机身份和源世代水位。SQLite 完整性与外键检查通过后才发布备份目录。
- 恢复只接受本机 `backups/` 中同宿主、同家庭、同迁移版本且可证明原生日志前缀一致的成品。先停止接入、Job 认领及发布，保存操作前检查点。业务状态一致时安装所选 SQLite。当前状态有可信后续变化时，保留整个操作前 SQLite 检查点并向用户明确说明，避免拆开撤回、墓碑、相关记录、收据和已提交效果。证明缺失、历史分叉或版本不匹配会拒绝恢复。
- 安装以原子文件替换和持久恢复记录衔接。候选 Bun 先只开放回环状态与 HTTPS 健康检查，手机、peer 和后台执行保持暂停。Swift 校验通过后才提交并释放候选进程。提交前发生失败或进程中断就回退操作前备份。回退验收失败会停服并保留恢复记录。提交后才出现的运行失败保留已验收的数据并停服。
- SQLite 恢复会轮换本机源世代，现有 peer 游标转快照，成员增量同步也用同一世代。恢复保留入站 peer 已核验水位、发布交接世代与确认收据，本机进程租约到期，群聊仍按已有交接证明和新的 peer 续租判断发布权。旧 SSE 游标走轮次快照。
- 管理契约为回环 `GET/POST /host/backups`、`GET /host/status` 的维护与世代字段，以及 Swift `BunHost.backup()`、`BunHost.restore(_:)`。旧 PG 备份和服务器继续走原有 `Cattt.app`。换机或当前 SQLite 已无法通过完整性检查时的灾难恢复另行实现。

运行命令、文件清单和整合接缝见 [macOS 宿主](../../desktop/macos/README.md#独立试用备份与恢复)。
