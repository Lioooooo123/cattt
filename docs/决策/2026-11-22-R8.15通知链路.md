# R8.15 约定提醒与 APNs

- iOS 用已验证并落盘的成员事项增量排系统本机通知。按家庭、成员、home host 隔离，同一事项用稳定的系统通知 ID。改期、取消收据先移除旧时间，再等待新事项投影。过期事项、墓碑及重复增量不会重排；短暂离线继续用本机已同步的时间。切换或取消配对后清掉旧空间的待发提醒；一旦查到配对凭证撤销也清掉对应提醒。
- 首次系统权限仍由成功保存的显式约定触发，已有授权沿用 iOS 系统设置。前台收到 v2 通知时刷新成员增量，静默展示；v1 本机提醒沿用原有行为。手机离线时，远端取消和管理员撤销要等手机再次连上宿主才可获知。手机主动解除配对会清理本机，旧宿主暂不可达时把撤销请求保留在钥匙串，回前台重试。
- 远程推送沿用 `REMOTE_PUSH_ENABLED=true`、`APNS_TEAM_ID`、`APNS_KEY_ID`、`APNS_PRIVATE_KEY_FILE`、`APNS_TOPIC`。默认关闭。开启时需要完整配置，`APNS_TOPIC` 与签名 App 的 bundle ID 一致，Debug 使用 sandbox，Release 使用 production。
- `PUT/DELETE /v2/device/push` 只操作当前 bearer 所属且仍有效的 home-host 配对设备。解除配对和移除成员清除绑定。设备 APNs token、供应商 UUID、投递状态和 outbox 留在发布宿主本地。
- Router 在既有 `publication_push_outbox` 上投递已提交的约定到期、托付完成和托付等待。每台设备发送前复核成员、家庭、chat/mailbox 收据、原话及来源修订、权限和当地安静时段。每天每成员最多两条，多设备共用一条额度；明确失败可以按同一设备收据重试，连接结果未知时不自动重发。APNs 200 代表 Apple 接受。手机点击远程通知后，由 `GET /v2/notifications/:id` 按当前配对解析实际消息或信件。
- 仅本人 home host 本地产生且具有发布收据的结果能发远程推送。另一个宿主发布的群聊事项在业务增量中可见，复制历史不产生远程推送。同一手机若开启远程推送，后台可能同时收到独立的系统本机提醒与 APNs 到期通知。
- SQLite 迁移 `0022_r8_15_notifications` 增加设备绑定和每设备投递收据。PG 导入保留既有的历史投递摘要，历史推送、凭证和 token 不进入新 outbox；手机需要重新配对并登记。真实 Apple 签名、APNs 接受和真机到达仍待验。
