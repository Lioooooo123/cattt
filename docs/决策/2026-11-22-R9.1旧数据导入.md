状态：已实现一次性导入和本机合成数据验收。4 台设备联调、生产备份及上线切换留待后续。

后续 R8.14 已加入旧猫资料与可核对 3D 观察的升级映射，见 [共享世界宿主](2026-11-22-R8.14共享世界宿主.md)。

## 导入与切换

用 [host README](../../host/README.md#一次性导入旧-postgresql-数据) 里的命令指定独立只读连接和空的目标目录。默认选旧库的 `host_owner`，只有一个账号时可退回该账号。多账号且无旧宿主主人时，用 `--legacy-user-id` 指定；每次仅导入一个账号及其猫和会话。新家庭第一个成员名为 Han，旧消息进 Han 的单聊，群聊从空历史开始。需要保留旧形状的证据带原始标识，SQLite 的 UUIDv7 按类型、旧标识、作用域及旧创建时间确定。消息和信箱用 PG 的 `seq` 排序，再生成有序 HLC，显示时间保留独立的旧墙钟值。

导入使用 `READ ONLY, REPEATABLE READ` 事务。SQLite 从正式内嵌迁移链建立，先写入目标目录下的私有临时文件，提交业务、核对账本及复制初始水位，再检查外键和完整性。最终以不可覆盖的文件链接提交 `cattt.db`；已有相同版本收据时，重读 PG 后验证快照摘要，返回原账本及 `verified`。快照变化和已有其他目标均拒绝。未完成写入的私有临时目录可以随下一次导入保留，重试不会复用其中的内容。收据验证的是导入输入与初始写入结果，启动后的正常业务修改由宿主继续管理。

首轮 peer 同步必须安装一个带撤回、权限和历史证明的原子快照；后续才从该水位拉增量。复制适配器校验普通业务归属及旧猫日记、旧记忆限制的原始家庭写者。旧消息的模型停用位随消息事实复制。Mac 间握手版本升为 6，设备 API 仍为 v2。当前 R6 快照接收上限为 10 万条复制记录，导入发布前使用同一快照闸口。归档、导入账本、执行记录和旧秘密留在各自存储边界。

## 逐表映射

| 旧 PG 表 | SQLite 目标或取证范围 |
| --- | --- |
| `users` | `households`、`hosts`、`members`、`proactive_permissions`；旧时区保留，有禁用项时也存 `imported_memory_restrictions`。开发 token 哈希不读。 |
| `cats` | 归档旧猫 ID、名字、外观、气质、特征、版本、记忆学习水位及偏好；时区和主动许可贯穿到上述设置。其余等共享猫、性格与 Soul 目标。 |
| `conversations` | Han 的 `conversations` 及 `participants`；保留旧会话版本为证据。 |
| `messages` | `messages`，保留猫/成员作者、文本、原顺序、完成/停止状态及可表达的客户端标识。合法旧来源挂 `reply_to`；原话停用写入 `knowledge_source_withdrawals`，停用的旧猫回复保留展示历史并排除模型输入。可验证的旧轮次引用进入 `chat_reply_knowledge`。 |
| `turns` | 本机 `turns`，未完成轮次结束为中断并保存旧状态。既有回复和可验证的触发消息保留关联。 |
| `turn_events`、`turn_controls` | 本机历史归档。 |
| `memories` | `memories`；Han 是可证实的本人主语及来源成员，旧修订从 0 基准换到 1 基准。只接旧权限允许且仍有效的本人事实。已知提问可存 `memory_extraction_dependencies`。第三人主语、缺源、撤回、冲突、已被取代与旧门禁拒绝分类留证；撤回和未证实来源不复制正文到归档。 |
| `memory_blocks` | `imported_memory_blocks` 保留旧算法指纹和 Han 的历史限制，避免用虚构消息填新表必填来源。归档保留受保护的旧序号范围。 |
| `memory_receipts` | 提问/来源/处理结果留证；旧提取收据不作为新作业。 |
| `boundaries` | `boundaries`；当来源为有效的 Han 原话才启用。空描述使用原话。 |
| `diary_entries` | 个人 `diary_entries` 保留当地日期、时区、正文、修订、猫是否可读；猫日记为同家庭只读的 `imported_cat_diary`，经 `GET /v2/cat-diary` 读取并可随 peer 快照复制。旧备注、访问位和客户端变更序列留证。 |
| `diary_facts`、`diary_calendars` | 日内活动事实与旧日程归档，等共享院子和猫日记调度批次映射。 |
| `tickets` | `tickets` 接证明完整的显式托付、约定和可核对旧原话哈希的推断事项。已发布事项映射到终态。开放旧约定保留日期和时区，进入可手动改期的 `quiet_waiting`，避免自动提醒；开放旧托付保留在可手动补充的暂停终态。日记生成类事项和无法证明来源的事项归档。 |
| `triggers`、`decisions`、`ticket_inputs` | 有配套旧命令、收据和决定时接只读历史，旧请求键加 `pg:` 前缀；无法唯一配对的补充、旧时钟触发、静默/拒绝原因留证。 |
| `runs`、`run_steps` | 有锚点的 `runs` 保留代次、当地执行日和已用预算，全部结束；`run_steps` 的完整模型输入、检查点、用量，及 `runs` 的旧汇报与依赖归档。新执行需要当前上下文和新代次。 |
| `mailbox_letters` | 已证明事项归属的 `mailbox_letters` 和 `mailbox_reads`；无事项关联的来信保留原文归档。 |
| `outbox`、`inferred_publications` | 已送达且以事项、同一 PG 事务时间和唯一内容交叉确认的记录进入 `ticket_publications`；推断发布额外核对原话和当地日。旧推送、含糊匹配及未发送记录只留证。 |
| `worker_reports`、`async_jobs` | 仅归档能够归到旧账号的待办、汇报和历史执行证据。 |
| `proactive_rules`、`inference_watches`、`inference_observations` | 规则版本及围绕旧原话的观察证据归档。 |
| `push_notifications`、`push_deliveries`、`push_budget_reservations` | 只保留必要的旧投递元数据；排除推送 payload、证明正文、设备及 APNs 关联标识。 |
| `model_calls`、`model_reservations` | 可归到旧聊天轮次或旧账号的模型用量与预算留证。 |
| `pairing_codes`、`paired_devices`、`devices`、`conversation_locks`、`model_admissions` | 仅计数；需重新为 v2 设备配对。PG-boss 自管 schema 不参与导入。 |
| `world_sessions`、`world_actions`、`cat_runtime_states`、`cat_runtime_events` | 原场景引用、位置/动作及状态演进归档，等共享院子状态及互动记录映射。 |
| `personality_versions`、`soul_versions`、`turn_soul_snapshots`、`soul_blocked_sources` | 原个人性格演进、Soul 版本/快照与撤回来源归档，等共享猫画像与 Soul 迁移。 |
| `runtime_calls`、`runtime_steps` | 旧聊天运行时调用、世界工具回执与分阶段记录归档。 |

账本逐表给出源内/域外行数、活业务行数、仅归档数、排除数和证据数。源摘要从一致快照内的排序 PG JSON 计算，秘密表只对计数取摘要。目标摘要从已读回 SQLite 的关键字段和对应证据计算。源与目标采用不同形状，目标校验以每行转换后的预期值为准。拒绝原因和逐行摘要可在本机 `pg_import_archive` 查到，数据复制不携带该表。

历史源权限限制没有新增配置入口。旧猫日记的生成、设备增量接入、共享 World/Soul 和跨设备硬件联调在后续批次继续。历史只读数据的回归覆盖真实 PG 17 迁移、独立只读角色、源码和编译入口、重复导入与目标保护、SQLite 失败后不发布目标、启动后的聊天/召回/日记/事项/信箱，以及 peer 快照安装时的撤回核对。测试数据库与旧库分开，旧 PG 目录继续保留。
