# 情侣共享与整体重构 · 2026-11-22

状态：Han 已批准重构计划 v4 及末尾七项默认值；R0 记录目标与实施边界，尚未实施新运行时、存储、协议或复制。

## 已定

1. 产品面向情侣：两名成员共同养同一只团子，每人一台 Mac 和一部 iPhone。两台 Mac 保存全量业务副本，两部 iPhone 通过各自宿主同步完整的业务内容；本机执行状态、凭证和模型密钥不作为共享业务复制。成员模型按 N 设计，产品先只开放两人。
2. 两人之间不设隐私隔离。群聊“我们仨”和各自单聊“我和团子”并存；伴侣的单聊不在另一人的界面展示，但不是存储保密边界。团子能理解两边的信息，转告须署名来源。“别告诉 TA”限制主动转告，不构成两人之间的隐私承诺；`cat_allowed` 继续控制团子能否读取日记。
3. 保留 TypeScript、自研 Agent 循环和 Hono；不改用其它服务端语言，不引入 AI SDK。Bun 作为服务端运行时与打包工具，用 `bun build --compile` 交付宿主可执行文件；SQLite（WAL）取代 PostgreSQL，使用 `bun:sqlite`、`drizzle-orm/bun-sqlite` 与 `sqlite-core`，不使用 better-sqlite3。
4. 每台 Mac 一个 Bun 主进程，逻辑上保留 Gateway、Inbox、前台 Router、Workers、Outbox、Replicator；worker 只计算和提交汇报，由 Router 统一复核并发布。需要隔离的计算优先评估 Bun Worker；只有确认 Bun Workers 足以满足隔离、取消和生命周期要求后才移除 `worker_threads` 路径，不把“合并进程”等同于取消执行隔离。
5. 保留 triggers → decisions → tickets、runs/run_steps 检查点、worker_reports 和 inbox/outbox 的领域语义。SQLite `jobs` 加进程内唤醒取代 async_jobs 与 pg-boss；`chat_events` 保留持久 SSE、取消与恢复语义，`leases` 统一运行互斥和发布宿主。
6. 从零设计新 schema 和 API v2，不兼容旧数据形状和 API v1；手机、Mac 协同升级。旧数据经一次性 `cattt import-pg` 导入，不保留长期兼容层；旧 PG 数据目录保留，删除前另行确认。
7. 单聊及个人事项由成员的 home host 发布；群聊、群聊事项和共享猫状态由群聊租约方单一写入。复制只同步数据，重放不触发行为；跨机行为由 peer outbox 投递对方 Inbox，以幂等键和持久收据保证业务效果不重复。
8. 统一 UUIDv7、应用层 Clock/HLC、按 host 的 change_log 与恢复世代、来源修订和删除墓碑；所有数据访问收口到仓储层，所有模型上下文按人装配，所有用户可见发布统一复核。
9. 仍在用户自己的 Mac 上运行，不提供托管服务，电脑端先做 macOS。第一版只支持局域网，transport 预留异地实现；本机 CA、短码和证书指纹固定保留，成员配对与 Mac 副本认证分开。
10. 聊天、Router 和托付使用 DeepSeek，记忆、边界、召回与日记使用本机 extract 槽位；沿用显式配置覆盖、预算、来源许可、撤回、有界工具修正与临时摘要规则。不把“记忆本机”表述成获准云端上下文绝不出机。

## 七项默认值：均已批准，不再待选

1. 成员数按 N 设计，产品只开放两人。
2. 不兼容旧 API，手机和 Mac 必须一起升级，不做兼容层。
3. 允许重构期间 main 暂时不能日常使用；计划 R1–R3 约一周不可用，旧版本打 tag 保留。时间是估计，不是可用性承诺；R0 不改运行代码，也不在本轮创建发布 tag。
4. 伴侣不能在界面上查看对方单聊；团子知道两边的信息，转告时注明来源。
5. 转告默认发到对方单聊，每人每天三条，紧急转告不受该条数限制；不豁免来源撤回、发布复核和用户明确不转告要求。
6. 第一版仅局域网，预留 transport。
7. 现有对话导入后归 Han 的单聊；旧记忆主语、来源和日记归属均为 Han，托付、约定与信箱保留。

- 替代 [手机配对与局域网 HTTPS](2026-11-19-手机配对与局域网HTTPS.md)“所有设备归同一主人”的身份模型；CA、短码、设备凭证和证书核对继续有效。
