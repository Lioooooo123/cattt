# 自有评测系统 · 2026-11-23

状态：聊天、托付、语义裁判与运行对比已实现，开发集实跑通过；不代表完整产品验收。

## 已定

1. 评测放在 `host/eval/`，使用 Bun、TypeScript 和 JSONL 套件，直接驱动生产接缝：聊天走 `ChatReplier + assembleChatRequest`，托付走 `registerTicketWorkers + JobRunner + dispatchTicketCommand`。
2. `scripted` 使用用例提供的回复或工具步骤，离线验证管线与上下文规则；`env` 使用宿主既有模型配置，验证真实模型行为。两者通过率不能当作等价模型质量比较。
3. 确定性 scorer 检查关键词、上下文、工具顺序、报告和预算等期望；可选 `--judge env` 按中文标准逐项评分。裁判使用温度 0 和严格 JSON，格式错误是失败，不算通过。
4. `compare` 生成总体、套件差值与退步、修复、新增、缺失用例，并支持通过率下降门禁。结果与原始 trace 放在 `host/eval-runs/`，可能含敏感原话，已忽略且不提交。

## 原因

Han 要求：“最后我们搭建一套自己的 eval 系统”。借鉴 [Lioooooo123/agent-evals](https://github.com/Lioooooo123/agent-evals) 的套件、评分与对比思路，但在 `host/` 内以 Bun 原生实现，不引入 AI SDK，让评测覆盖真实存储、上下文和工具执行接缝，而不是另造一条模拟业务链路。

## 实跑与边界

2026-11-23，DeepSeek `deepseek-flash` 以 `--suite all --mode env --judge env` 实跑 14/14 通过：聊天 10/10，托付 4/4；裁判使用同一供应商。与 scripted 基线对比无退步，总体允许下降 5 个百分点、聊天套件不允许下降两条门禁均通过。这只是小规模开发集 smoke，不是泛化质量结论。

- 聊天未覆盖 HTTP/SSE、持久 turn 与完整前台调度。
- worker 目前仅支持无额外记忆、边界和历史的单聊 setup，不启用工具历史摘要。
- 小开发集可能漏掉真实长对话和复杂工具失败；同供应商裁判可能共享偏差，不能替代独立人工评审。
- 原有 memory-eval 保持独立，未迁移。命令与详细限制见 [评测说明](../../host/eval/README.md)。
