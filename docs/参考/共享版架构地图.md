# 共享版架构地图

[v4 目标架构](../方案/情侣共享团子目标架构-方案-2026-11-22.md)定义逻辑分工。这里记录当前代码入口：每台 Mac 只运行一个 Bun 宿主；两台 Mac 各有自己的 SQLite、文件仓和配对身份。iPhone 访问所配对的宿主，不直接连接另一台 Mac。旧版 Node.js / PostgreSQL 留在 [server/](../../server/README.md)，不参与共享版运行。

## 客户端到宿主

- [iOS](../../ios/README.md)：SwiftUI 承载聊天、日记与本机缓存；小院通过 WKWebView 嵌入 [web/](../../web/) 的 Three.js 页面。设备走 API v2、聊天 SSE 和成员增量接口。
- [macOS](../../desktop/macos/README.md)：Swift 宿主管理 Bun 子进程、配对和备份恢复；桌面窗口复用本机 API v2 与内嵌小院。Web 展示页本身不是另一套业务客户端。
- [Bun 入口](../../host/src/main.ts)管理进程与恢复放行，[runtime](../../host/src/runtime/application.ts)组装组件，[Store](../../host/src/store/index.ts)管理 SQLite 连接、迁移与事务。

## 宿主组件

| v4 分工 | 当前代码 | 数据流和限制 |
| --- | --- | --- |
| Gateway | [gateway/](../../host/src/gateway/)、[peer/](../../host/src/peer/) | 回环管理 HTTP、成员 HTTPS/SSE、宿主间 mTLS。负责身份与协议准入，不决定团子该说什么。 |
| Inbox | [conversations/routes](../../host/src/conversations/routes.ts)、[peer-behavior/](../../host/src/peer-behavior/)、[ticket-intake](../../host/src/store/ticket-intake.ts) | 分布在各入口；成员请求、明确的 peer 行为与事项准入各有持久收据或幂等键。 |
| Router | [TurnRunner](../../host/src/turns/index.ts)、[ReportRouter](../../host/src/router/index.ts)、[group-sends/](../../host/src/group-sends/) | 聊天轮次、群聊转投与汇报发布分在不同入口；共享群聊还受发布租约约束。发布前复核来源和许可。 |
| Workers | [jobs/](../../host/src/jobs/)、[ticket-workers/](../../host/src/ticket-workers/)、[memory/jobs](../../host/src/memory/jobs.ts)、[daily-diary](../../host/src/soul/daily-diary.ts) | SQLite 作业队列负责任务认领；记忆、日记和托付计算不经过复制端点。托付执行写汇报，由发布链路复核。 |
| Outbox | [chat-events/](../../host/src/chat-events/)、[report-publications](../../host/src/store/report-publications.ts)、[publication-push](../../host/src/store/publication-push.ts)、[peer-behavior/](../../host/src/peer-behavior/) | 聊天回放、信箱、APNs 与显式 peer 投递各有持久状态，不是一个统一目录或队列。 |
| Replicator | [replication/](../../host/src/replication/)、[store/replication](../../host/src/store/replication.ts) | 拉快照、增量和文件块，维护游标并合并数据；不投递行为、不跑模型、不发布新消息。 |

## 耦合点

| 位置 | 观察与处理 |
| --- | --- |
| Peer 传输与业务 | 原来同一处绑定 mTLS、快照和文件复制、发布租约、家庭名额及小院在场。现在 [runtime/peer](../../host/src/runtime/peer.ts)负责业务接线，传输层负责认证、版本、请求分派和连接状态；复制和行为共用监听，不共用处理流程。 |
| Router 和投递 | 汇报扫描、推断、转告和 APNs 共用 [ReportRouter 的扫描生命周期](../../host/src/router/index.ts)。后续若拆分，可让持久化待发送记录继续作为交界，避免重做发布判断或新增并发认领者。 |
| Store 与派生记录 | 某些业务仓储在事务内同时追加业务状态、变更日志和投影。这部分是原子性要求，不改成提交后的进程内事件。 |

仍使用原有 API v2、peer 协议版本、数据库和启动方式。不拆进程，不改权限、发布规则或重试策略。
