# 工作约定

这里是项目怎么干活的规矩。它们原来散在 AI 助手的记忆和各轮方案里，2026-09-12 收进仓库；以后改规矩就改这一篇，并在决策记录里写一句。

## 真相源

- **仓库是唯一真相源。** 飞书（已不再同步）、`~/Documents/Codex`、`~/Documents/ChatGPT/猫/outputs` 的出图目录、AI 助手的记忆、个人笔记，都只是输入。
- 一条信息要算数，必须落进仓库：
  - 决定写进 `docs/决策/<日期>.md`，只记"定了什么"。
  - 要写方案时，推导和做法写进 `docs/方案/`，登记到 [文档索引](README.md)。
  - 素材放 `assets/`，出图交付和验收证据放 `outputs/<轮次>-delivery/`、`outputs/<轮次>-review/`。
- 提方案前先读最新的决策记录。已经定了的事不重新提案，要推翻就明确写"推翻哪一条、为什么"。
- 决策记录只增不改：被推翻的旧内容不删原文，在原处标注"已被 某日 推翻"。方案、讨论稿一类整篇过时的，直接从当前版本删除（`git rm`），在决策记录里写一句为什么、给个替代指向。
- 删掉的东西原件都在 git 历史里：`git log --diff-filter=D --oneline -- <路径>` 找删除它的提交，再 `git show <提交>:<路径>` 取回。文档里出现的 `docs/archive/...` 旧路径也是这么取。
- 产品文档在 `docs/产品/`（原飞书三份文档，2026-09-12 整合进仓库），直接在仓库里改，不再与飞书同步。需要从飞书取外部参考资料时用本机 `lark-cli`，不走浏览器，取回的内容要整理进仓库才算数。

## 节奏

- **方案按需，不是每次开发的必经步骤。** 用户点名要方案或评审时才先写进 `docs/方案/`，评审过再动代码；平时直接改、跑验证。要写方案时走：讨论 → 方案 → 评审 → 实施 →（需要时）实施与验收记录。
- 删除、推送、改外部服务等不好撤回的动作，先确认。
- 视觉提案要分开"系统"和"画"：手写 SVG、代码画的图只能当配色、版式、结构的示意，不能当画风提案。评判视觉用三条独立标准：**有特色**（角色设定与世界规则）、**好看**（执行精度）、**耐看**（信息密度与配色克制）。

## 出图委托

出图模型不在本仓库的工具链里：委托单写进 `assets/<对象>/<轮次>/brief.md`，交给出图模型（Codex 等），交付物放回 `outputs/<轮次>-delivery/`。**这一节讲的是 2D 世界层的产线；2026-09-27 起 2D 冻结（[决策](决策/2026-09-27-3D为准线.md)），新素材走 3D：`assets/yard-3d/`、`assets/tuanzi-3d/`。**

1. **单张全幅，不出网格。** 网格会挤压主体、让头身比缩水。动作帧确需多格时，每格留足空间、写死同一尺寸，并逐格验收。
2. **已通过的不重掷。** 只重出不合格的那一张。
3. **失败必须上报，禁止拿旧图顶替。** 交付附 `delivery.json`，每个编号一条，状态只能是新生成、失败、没做。
4. **一次只改一件事。** 同时给两处修改，对方会改错对象。
5. **图参考优先于文字。** 有锚点就传图；角色基准只用 `assets/tuanzi/canonical/` 与世界层已确认的参考图。
6. **第二次否决就停下重新对齐。** 两次"不好看"说明分歧在主题，先重述这张图要说的一句话。

判据先行：出图前定可测的判据（色相角距、暗部占比、头宽、重合度……），出图后先量数再看图。判据本身不成立时当场作废并写明原因。

## 收图验收

按五道关顺序过，前一道不过不看后面：

1. **清点**：编号、清单、目录三方对齐。
2. **哈希**：和历史素材比 SHA-256，撞上就是旧图顶替。
3. **格式**：画布尺寸、背景、透明通道。
4. **内容指纹**：按类型量（连通块、色相占比、朝向、比例、配准残差……）。
5. **人眼**：数字过了才看图；美术目标请用户看。

脚本在 `assets/tools/`：`intake_rig_v1.py`、`intake_frames_v5.py` 是收图验收，`package_frames_v5.py` 是切帧打包，`configure_world_v5.py`、`configure_world_v6.py` 是场景配置（原地修改），`package_frames_v6.py` 是 v6 切帧，`make_rain_sound.py` 合成雨声，`validate_world_v4.py` 是构建后的资源校验。验收报告和锁定记录写进 `outputs/<轮次>-review/验收报告.md` 与对应素材目录的 `README.md`。

## 构建与验收

- 工程文件由 `ios/generate_project.py` 生成，增删文件后重跑；不要手改 `project.pbxproj`。
- 世界层纵深用了 Metal 着色器，新机器第一次编译前要装 Apple Metal 工具链：`xcodebuild -downloadComponent MetalToolchain`。
- 场景配置 `world-scene-v4` 不要用 `configure_world_v4.py` 重新生成（会抹掉后来直接加进去的信箱等物件），改动用 `configure_world_v5.py` 这种原地修改的脚本。
- 世界层以 3D 为准线（`web/`、`assets/yard-3d/`、`assets/tuanzi-3d/`）；Swift 2D 世界层与逐帧素材已冻结（[决策](决策/2026-09-27-3D为准线.md)），只修阻断性 bug。
- 本机能跑的全部检查一把跑：`sh tools/check_all.sh`（世界层逻辑测试、跨端规则、网页与后端类型检查）；资源校验另见根 [README](../README.md#跑起来)。
- **模拟器验收**：iPhone 17 Pro / iOS 26.5。先 `xcrun simctl boot`，再用模拟器面板或 `xcrun simctl io booted screenshot`、`recordVideo`。App 的调试启动参数 `-script "延迟ms:命令:参数;…"` 可以驱动世界层，命令见 `ios/Maomao/Debug/DebugScript.swift`，常用的有 `place:地点`、`moveCat:地点`、`findCat`、`speed:0.25`（慢放）、`snapshot:名字`，时段与情绪用 `time:19.6`、`weather:rain`、`mood:sad`、`bowl:fill`、`drink`、`diary`。
- 模拟器的文字输入只能打 ASCII，中文消息用启动参数 `send:文本`；连本机后端用 `-backendMode local -backendToken <token>`。
- 图像处理用装了 Pillow 和 numpy 的 Python（本机是 `/Library/Frameworks/Python.framework/Versions/3.14/bin/python3`）。已知坑：Pillow 12 里 `Image.fromarray()` 得到的图做 `ImageDraw.floodfill` 会静默失败，要先 `Image.frombytes` 复制一份。

## 本机后端的坑

- colima 虚拟机的钟比宿主机慢约 22 秒。凡是和数据库 `now()` 比较的时间，都用数据库的钟（代码里是 `dbNow()`）。
- `tsx watch` 的子进程被强杀后不会再重启；测强杀要单独用 `node --import tsx src/api.ts` 起服务。
- pnpm 11 默认拦安装脚本，`pnpm-workspace.yaml` 里的 allowBuilds 已配好。
- 项目的模型 key 变量叫 `MAOMAO_DEEPSEEK_API_KEY`，特意避开全局的 `DEEPSEEK_API_KEY`，免得被 shell 里的旧 key 盖掉。启动日志会提示哪些变量被环境覆盖。
- macOS 没有 `timeout` 命令。

## 落盘规矩

- **出图交付** `outputs/<轮次>-delivery/`：只放最终挑中的；废稿在 `_rejected/`，可以提交但不要超出必要。
- **验收证据** `outputs/<轮次>-review/`：只放报告、数值、汇总对照图，单张不超过 1MB；模拟器原尺寸截图、逐帧抽图、录屏只留本地。
- **不做整份备份**：改动前不要把代码和资源复制一份放进 `outputs/`，git 历史就是备份。
- **日志**：构建日志不提交；测试结果写进验收报告，需要留原始输出就存成 `*-tests.txt`。
- 本机缓存（如 `assets/registry/` 的哈希库）不提交。

## 提交

- 只在用户要求时提交、推送。提交信息用英文祈使句开头，写清改了什么、为什么。
- **提交前检查**：`tools/repo_check.py` 与 `tools/check_shared_rules.py` 挂在 git 的 pre-commit 钩子上（`git config core.hooksPath .githooks`，每台机器设一次）。前者拦下：
  - 单个超过 3MB 的文件，除非登记在 `.repo-allow-large`。
  - 日志、录屏、构建产物。
  - 新增的 `docs/决策/*.md`、`docs/方案/*.md` 没有登记到 [文档索引](README.md)。
  后者拦下跨端漂移：行为参数表（iOS `Personality.swift` ↔ 后端 `runtime/behavior.ts`，按 4 种气质 × 81 组特征跑出来逐字段比）、氛围关键帧（`Atmosphere.keyframes` ↔ 网页 `KEYFRAMES`）、地点表（scene.json ↔ 后端 `destinationIds` ↔ iOS `Location.all`）、场景版本，以及 `web/src/yard/layout.generated.ts` 是否与生成脚本同步。
- 提交前先跑一遍 `sh tools/check_all.sh`（仓库内容 + 跨端规则 + iOS 世界层测试 + 网页 typecheck/测试 + 后端 typecheck）；`.github/workflows/checks.yml` 用同一批命令。后端集成测试要本机 PG，单独跑 `cd server && pnpm test`。
- 真要绕过，用 `git commit --no-verify`，并在提交信息里写原因。

## 每轮收尾清单

一轮工作结束、提交之前过一遍：

1. 新的决定写进 `docs/决策/<日期>.md`，登记到文档索引。
2. 被推翻的旧内容在原处标注；整篇过时的从当前版本删除，从索引里去掉，在决策记录里写一句。
3. 实施记录的状态行（"待评审 / 已实施 / 未提交"）改成真实状态。
4. 中间产物、原尺寸截图、录屏没有混进暂存区。
5. 仓库外有没有新的"真相"（出图原件、飞书改动、口头决定）需要收进来。
