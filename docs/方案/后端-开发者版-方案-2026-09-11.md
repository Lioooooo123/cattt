## 1. 这一版做什么、不做什么

**做：**

1. 开发者 token 登录（每人一个 token，脚本生成）。
2. 创建和修改一只猫：名字、外观、气质、四条特征，对应 iOS 创建流程已有的字段。
3. 文字聊天，流式回复；消息先落库再生成。
4. 断线后续上同一条回复；停止按钮保留已生成的字；用户在等回复时补一句，旧回复作废重来。
5. 回复之后异步提取长期记忆，下一轮召回；用户说「记住……」要记下。
6. 「不要再提」写进边界，之后不再提。
7. 记忆可查看、可删除；删了不会被重新提取出来。
8. 每轮回复有运行记录和 token 用量。

**不做（留到后面）：** 部署、Sign in with Apple、账号删除与导出、语音、图片、主动消息与定时续聊、话题库、关系日记、语义（向量）召回、限流、多实例。
向量召回不接 embedding，也不提前建向量列（维度取决于以后选的供应商），本机用带 pgvector 的镜像留好余地。开发者版按文档写的降级方式召回：固定的加最近的。

## 3. 仓库和 Railway 怎么摆

这个仓库本身就是 monorepo，只加一个 `server/` 目录。Swift 和 TS 之间没有类型可共享，不上 Turborepo、Nx、pnpm workspaces。

```
server/
  src/
    api/        路由、SSE
    runtime/    组装上下文、调模型（CatRuntime）
    worker/     BullMQ 任务：记忆提取、边界整理、清理卡住的回复
    db/         Drizzle 表定义
  drizzle/      迁移 SQL
  scripts/      create-dev-user 等
  docker-compose.yml   本地 PG（pgvector 镜像）+ Redis
```

**本机（这一版）：** colima 起 Docker，`docker compose up` 起 PG 和 Redis，`pnpm dev` 同时起 api 和 worker。iOS 模拟器连 `http://localhost:8787`。

**以后部署时**，Railway 一个项目，四个服务：

| 服务 | 来源 | 说明 |
|---|---|---|
| api | `server/`，启动命令 `node dist/api.js` | 对外；健康检查 `/healthz`；部署前命令跑迁移 |
| worker | `server/`，启动命令 `node dist/worker.js` | 不对外 |
| Postgres | 带 pgvector 的模板 | 开备份 |
| Redis | 官方模板 | 淘汰策略必须是 noeviction（BullMQ 要求） |

- api 和 worker 都设 **Root Directory = `server/`**、**Watch Paths = `server/**`**。仓库 `.git` 1.3G、`assets` 349M，不设的话提交一张猫图也会触发后端重新部署。
- 服务之间走 Railway 内网。
- 设置部署排空时间（`RAILWAY_DEPLOYMENT_DRAINING_SECONDS`），让重新部署时正在生成的回复能跑完。

## 4. Redis 放什么

**原则：Redis 里只放丢了也不要紧的东西，该留的都在 PG。**Redis 整个清空，最坏结果是正在进行的那一条回复断掉，客户端重试即可。

| 用途 | 键 | 说明 |
|---|---|---|
| 任务队列 | BullMQ 的 `memory-extract`、`boundary-summarize`、`sweep` | jobId 用 `源消息 id:任务类型:版本`，重复投递不重复执行；PG 唯一约束兜底 |
| 回复续传 | `turn:{id}:stream`（Redis Stream） | 生成的每一段都 XADD 进来，完成后保留 10 分钟。客户端断线后带 Last-Event-ID 从断点接着读 |
| 停止与作废 | `turn:{id}:cancel` | 停止按钮和「补了一句」都写这里，生成循环每段检查一次 |

**不放：**会话、用户资料、记忆的缓存。开发者版没有这个性能需求，多一层缓存就多一个一致性问题。

## 6. 一轮回复怎么走

1. **收消息**：同一个事务里存用户消息、conversation.version +1、建 turn（记下 input_version）。client_message_id 重复就返回已有的那一轮，不新建。
2. **回 `accepted`**：iOS 收到后气泡从「发送中」变成已发送。
3. **后台生成**：api 进程里起一个和 HTTP 连接无关的任务跑生成。每段写进 Redis Stream，HTTP 响应只是跟着读这个 Stream 往下发。
   所以客户端断了，生成照样跑完、照样落库。
4. **组装上下文**：猫的性格（稳定，放缓存断点前）→ 边界 → 召回的记忆 → 最近 30 条消息。
   召回 = 用户明确要记的 + 最近 20 条有效记忆，排除阻断的。
5. **新鲜度复核**：发第一段之前查一次 version，变了就发 `superseded`，这一轮作废；新消息进来时也会立刻通知还没开口的旧轮次作废，不用等到它吐第一个字。
   **已经开口的不作废，让它说完**（实施时改的：字已经在屏幕上了，再撤回更怪）。同一段对话有一把 Redis 锁，同一时间只生成一轮，新的一轮等前面说完才组装上下文，所以前面那句和补的那句都在上下文里。
6. **提交**：一个事务里存猫的消息、turn 标记完成、写 model_calls，然后发 `done`。
7. **入队**：投一个 `memory-extract` 任务。

**停止**：写 cancel 标记，生成停下，已生成的字按 stopped 存库。
**卡住**：生成时每 5 秒写一次心跳。worker 每 15 秒扫一次，30 秒没心跳的标记为 failed，客户端续传时会收到可重试的 `stale` 错误。
心跳和判定都用数据库的钟（本机 Docker 虚拟机比宿主机慢 22 秒，混用两边的钟会判错）。

**记忆提取（worker）**：取这一轮的用户消息、猫的回复和前几条消息，用结构化输出拿到候选列表，然后按顺序过筛：

1. 高敏感的，除非用户明确要求记，否则丢掉。
2. 置信度低于阈值的丢掉。
3. 指纹命中 memory_blocks 的丢掉。
4. 同一 subject + predicate 已经有有效记忆的：用户明确纠正时，旧的标记为 superseded；否则两条都标记为 conflicted，降低召回优先级。

## 7. 接口

全部带 `Authorization: Bearer <dev token>`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/messages` | body `{client_message_id, text}`，响应就是 SSE 流 |
| POST | `/v1/messages/:id/reply` | 对已有用户消息重新回复（超时后「再试一次」），响应是 SSE 流 |
| GET | `/v1/turns/:id/stream` | 断线续传，带 `Last-Event-ID` |
| POST | `/v1/turns/:id/cancel` | 停止。body 可带 `visible_length`（屏幕上已显示的 UTF-16 长度）：从按停止到服务端真停住，模型还会多吐几十个字，存库时截回到这里 |
| GET | `/v1/turns/:id` | 这一轮的状态、用到了哪些记忆（memory_ids）、提取完没有、是否记下了用户明确要记的（remembered） |
| GET | `/v1/boundaries` | 「不要再提」列表，「我的」页的边界数用它 |
| GET | `/v1/messages?before=&limit=` | 历史消息。猫的消息带 `remembered`、`boundary` 两个标记，重开 app 后「记下了」「已经记下了」的注文还在 |
| POST | `/v1/messages/:id/boundary` | 不要再提 |
| GET / DELETE | `/v1/memories`、`/v1/memories/:id` | 查看、删除记忆 |
| GET / PUT | `/v1/cat` | 读取、创建或修改猫 |
| GET | `/healthz` | |

SSE 事件是我们自己定的，不用原模型库 的流协议，免得 SDK 升级牵连 iOS 发版：

```
id: 7
event: delta
data: {"text":"嗯"}
```

| 事件 | data |
|---|---|
| accepted | `{turn_id, user_message_id}` |
| delta | `{text}` |
| superseded | `{turn_id}` |
| done | `{message_id, status: "done" \| "stopped"}` |
| error | `{code, retryable}` |

error 的 code：

| code | retryable | 什么情况 | iOS 该怎么显示 |
|---|---|---|---|
| model_error | 是 | 限流、超时、模型服务 5xx | 「它走神了 · 再试一次」 |
| stale | 是 | 服务端进程中途挂了 | 同上 |
| busy | 是 | 前一轮 60 秒还没说完 | 同上 |
| empty_reply | 是 | 模型什么都没说 | 同上 |
| model_quota | 否 | 模型账户余额不足 | 不给重试按钮；开发者版直接提示余额不足 |
| model_auth | 否 | key 不对或没权限 | 不给重试按钮 |
| model_bad_request | 否 | 请求格式被模型拒绝，是我们的 bug | 不给重试按钮 |

## 8. iOS 怎么接

**实际做法（09-12）：** 没有抽协议。本地模拟那套原样留在 `AppStore.swift`，接后端的写在 `AppStore+Remote.swift`；`send` / `retry` / `stopStreaming` / `markBoundary` 开头判断一下走哪边。多一层协议换不来什么，两套逻辑的时序也不一样。

- 网络层在 `ios/Maomao/Backend/Backend.swift`：REST 接口 + 自己写的 SSE 解析。`URLSession.AsyncBytes.lines` 会吞掉空行，而 SSE 靠空行分隔事件，所以按字节切行。
- 调试面板最上面是「后端」：本地模拟 / 本机后端（localhost:8787）、token 输入框、重新连接。设置存在 UserDefaults。
- 模拟器验收可以用启动参数：`-backendMode local -backendToken … -backendURL …`，脚本命令加了 `backend:`、`send:`、`stop`、`boundary`。
- 接后端时拉最近 50 条历史，「我的」页的记忆数、边界数也从后端取。连不上时聊天为空，不显示本地模拟的示例对话。
- 创建流程走完会把名字、外观、气质、四条特征写到服务端（`PUT /v1/cat`）。

现有七个状态和事件的对应：

| 状态 | 什么时候进 |
|---|---|
| sending | POST 发出，还没收到 `accepted` |
| sent | 收到 `accepted` |
| failed | 收到 `accepted` 之前请求失败。重试用同一个 client_message_id，服务端不会存两条 |
| streaming | 收到第一个 `delta` |
| stopped | 用户按停止：界面立刻停住，cancel 时带上屏幕上已显示的长度，服务端只存这么多 |
| timeout | `accepted` 后 20 秒没有 `delta`，或收到 `error{retryable}`。「再试一次」调 `/reply`，不再重发用户那句 |
| done | 收到 `done` |

- 连接断了但这一轮还没结束：自动调 `/turns/:id/stream` 续传，不改气泡状态。
- 「记下了」：记忆提取是异步的，`done` 的时候还不知道。`done` 之后每 2 秒查一次 `/turns/:id`，最多 10 秒，提取出明确要记的记忆就给气泡打上 remembered。
- `markBoundary()` 调 `/boundary`。

## 9. 模型

两处都用 DeepSeek V4.1 Flash，API 模型名 `deepseek-flash`（09-10 发布；旧名 `deepseek-v4-flash` 仍被接受并转到它）。

- **这个模型默认开思考**（effort high），首字会明显变慢。主对话显式关掉思考。
- 记忆提取也先关思考，用 JSON 输出；提取质量不够再开 low。两处都用环境变量配，不写死。
- DeepSeek 自动做前缀缓存，命中价约为未命中的五十分之一。性格那段放最前面、每轮不变；记忆和最近消息放后面。
- 价格分高峰和低谷，高峰是 UTC 周一到周五 01–04 点、06–10 点，即北京时间 9–12 点和 14–18 点。开发测试不用在意，账本里照实记 token。

- 09-11：第 1–3 步，假模型下 `pnpm smoke`、`pnpm test` 全过；强杀和正常重启 api 两种情形手测通过。
- 09-12：第 4 步 iOS 接入，模拟器上用真模型走通发送、流式、「记下了」、发送失败后重试、「不要再提」、停止、「我的」页两个数；断线续传用一个可以随时掐断的 TCP 中转实测，App 自己带着最后的事件 id 续上了。
  顺手修了三处：停止时存下的字比屏幕上多（改成带 `visible_length`）、模型输出里的空行在气泡里是一大块空白（服务端把连续换行压成一个）、重开 app 后注文丢了（历史接口带上两个标记）。`pnpm smoke` 现在 11 项。
09-12 用真模型（deepseek-flash，关思考）跑了 4 句：首字第一句 3.4 秒（冷启动），之后 1.0–1.3 秒；「记住我对猫毛过敏」被记下并在后面答对；「下周五考雅思」换算成了 2026-09-18；前缀缓存从第二轮起命中 128–384 token。
回复语气有两处要调：「趴窗台上等了好久，还以为你今天不回来了」有点让人愧疚，「你上次累成那样，是不是就在看这个」是没根据的猜测。性格提示词留到接完 iOS 一起调。

**已知取舍：** 删除记忆后，阻断按「哪一方面」（subject + predicate），不按具体内容。删了「喜欢的饮料：拿铁」之后，「喜欢的饮料：美式」也不会被自动记下，除非用户明确说「记住」。这样偏保守，但阻断记录不存原文就没法判断内容像不像，换个说法绕过阻断更伤信任。
