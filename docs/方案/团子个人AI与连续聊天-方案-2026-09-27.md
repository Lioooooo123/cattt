## 1. 要交付的体验

用户从院子、日记或话题入口进入的都是**同一个聊天框**：重开 App、滚动到旧消息、网络中断后继续看回复，都能回到同一段对话。团子能在当前提问确实相关时记起用户以前明确说过的事；用户可以更正、删除或禁止使用这些事。它可以按请求帮助整理想法、查天气或推动院子里的可执行动作，同时保留团子的性格、简短语气与关系边界。没有模式选择、会话列表、亲密度数字或让用户负担的提醒。

“像 Muse”在本方案中指一个长期、可控的个人 AI 入口，以及合适时机使用过去的信息；Muse 的多应用连接、后台任务和主动建议是后续能力的参考，不直接成为本轮实现范围。主模型使用 DeepSeek 与自研工具循环；供应商切换和上线部署另行评估。

## 2. 当前事实与缺口

| 方面 | 现状 | 缺口 |
|---|---|---|
| 聊天归属 | `conversations.cat_id` 唯一；鉴权绑定用户、猫与唯一 conversation；没有创建或选择会话 API | 后端已经满足单对话，删除该表会破坏消息归属、新鲜度版本和重试 |
| 历史 | `GET /v1/messages?before=seq&limit=…` 支持倒序分页后返回正序；iOS 接入时只取最近 50 条 | 旧记录在库中，却不能在聊天框里继续上翻；消息上的“记录”入口仍未完成 |
| 回复 | turn 有持久状态和 SSE 续传；iOS 的活动 turn ID 与事件位置只在运行中的任务里 | App 进程退出后无法定位尚未结束的回复；接受前失败与接受后失败需要分别恢复 |
| 个人记忆 | 上下文取最近 30 条原始消息、明确记忆与近期有效记忆；提取在回复后异步进行 | 更早但相关的信息不能稳定进入上下文；现有召回未做相关性检索 |
| 控制 | 记忆可查看和删除，删除按 subject + predicate 阻断再提取并使相关 Soul 来源失效；可给猫消息标“不要再提” | 缺少更正；原始消息仍可进入最近窗口；iOS 的气泡“删除”只改本地，刷新会回来 |
| 身份 | `world_sessions` 标记设备连接与动作代次；turn 是一次生成尝试 | 它们不是可见聊天会话，不宜随“取消 session”删除 |
| 表达 | 团子的当前提示词写了“你是一只猫，不是助手”、一到三句、不主动给建议 | 要能按需帮助，又不能突然变成无差别的通用助手 |

依据代码：`server/src/db/schema.ts`、`server/src/db/schema-world.ts`、`server/src/runtime/context.ts`、`server/src/runtime/persona.ts`、`server/src/api/chat.ts`、`server/src/worker/memory.ts`、`ios/Maomao/Backend/Backend.swift`、`ios/Maomao/Store/AppStore+Remote.swift`、`ios/Maomao/Features/Chat/MessageRow.swift`。以上为静态调查，不代表在当前机器上完成运行验收。

## 3. 数据对象与“取消 session”的边界

- **对用户：**只有团子的一段聊天，所有聊天入口返回这一段；不显示“新建会话”、会话 ID 或会话切换。跨天只是时间变化，不重置聊天或猫的关系。
- **服务端：**保留唯一 `conversation` 作为持久消息的归属、`version` 新鲜度检查和分页范围；保留 `turn` 作为生成、取消、重试、记忆记录的单位。内部名称不出现在界面上，无需为消除术语做破坏性迁移。
- **世界：**保留 `world_sessions` 与 generation；设备断开或切换只改变动作执行权限，不开启新聊天，也不清空记忆。世界观察必须有时间和回执；`accepted` 不能说成 `arrived`。
- **长期记忆：**用户事实／偏好有来源消息、作用域、版本与状态；当前聊天窗口只负责近期连贯。话题、Soul 成长、院子事实和日记分别存储，不能把派生日记当成用户说过的事实。跨应用信息若以后接入，先定义每个来源的单独许可。

## 4. 推荐实施顺序

### 第一段：让唯一聊天真的连续

1. **历史分页。** iOS API 客户端传 `before`，保留服务端 `seq` 和消息 ID；聊天顶端加载更早一页，按服务端 ID 去重，插入旧页时保住当前可见位置。首次加载仍可用最近 50 条，不以一次请求下载全量记录；空页标记已到头。现有“记录”入口改为此聊天内定位历史的入口，或在实现前隐藏，不能造出第二段聊天。界面实施前先按 `maomao-ui` 检查表核对。
2. **重启恢复。** 给现有唯一 conversation 的消息历史或一个归属校验的查询接口补上相关 turn 的 ID 与状态，使客户端能找出最新待处理的用户消息及其当前 turn。进程启动后先加载历史，再根据 `queued/generating/completed/stopped/superseded/failed` 重接或显示终态；对已被服务端接收的用户消息仅重接原 turn 或对原消息调用 `/reply`，不重新发送成新消息。发送前的本地草稿继续复用 `client_message_id`。若网络不可用，保留可重试标记，联通后再对账；终态快照以持久消息为准，避免重出猫气泡。
3. **区分控制语义。** 当前 iOS “删除”会造成刷新后复现，先停用这项误导性的服务端聊天删除暗示；待第 5 节的删除契约实现，再开放对应操作。留在本地的未发送草稿可单独移除。服务端“不要再提”必须只接受归属内的**猫消息**，阻断与记忆删除彼此独立。

### 第二段：按相关性记起用户，并能纠错和遗忘

1. **先校正数据规则。** 新增经鉴权的记忆更正入口：用户编辑值后生成新有效版本和更正来源，旧版本停止召回；同一方面不再让晚完成的旧提取覆盖用户更正。更正来源、修改时间与操作者类型可审计；模型不可直接写这些状态。自动提取仍只依据用户消息，高敏感内容仍需明确同意。
2. **检索只作用于候选记忆。** 从当前输入和最近若干条构建查询，固定的明确记忆、语义相关记忆和近期记忆分路取候选，去重后只注入少量有效项。使用现有 Postgres 与 pgvector 环境做候选向量存储的技术验证；embedding 提供方、维度、版本、费用与延迟在实施前实测确定，不凭“数据库镜像带 pgvector”推断扩展或索引已经启用。索引异步补齐，先写事实来源再生成向量；不对全部原始聊天做无边界的向量搜索，不把向量相似度当发言许可。
3. **硬门优先。** 检索前后都校验用户／猫归属、来源状态、删除阻断、冲突、敏感度和“不要再提”；相关性只决定排序。必须能回溯每轮注入的 `memory_id` 与来源，保留现有 turn 的记忆引用；检索失败则退回明确记忆与近期有效记忆，权限或来源校验失败时宁可不注入。
4. **明确遗忘语义。** “删除记忆”删除该方面的全部记忆版本和向量，保持阻断，不再作为长期记忆使用；如果来源消息还在近期原始窗口，单删派生记忆**不能保证模型忘记那段原话**。因此在 UI 文案区分“删除记忆”和“删除聊天记录／不再使用这段内容”，并在真正提供后者前设计来源级排除或删除：构建上下文、提取、检索、摘要、Soul、话题及正在生成的回复都要在同一个撤回状态下复核。旧的记忆阻断只允许由撤回之后用户**再次明确要求记住**的消息解除；不能让旧任务重放解封。高敏感及第三方事实默认不自动提升为可主动提起的关系材料。
5. **消息删除需单独验收。** 若用户选择删一条或一段原始对话，先定义其影响范围与确认交互，再用鉴权操作处理消息、相关 turn、异步任务、记忆来源、向量、摘要／话题／Soul 派生对象，以及正在生成的结果。避免简单级联使 turn、世界回执或其他记录悬空；删除后不得因历史加载或异步重试重新出现。账号级导出／删除另立方案，不以本操作代替。

### 第三段：帮助、关系和主动事项

- **表达与能力。** 将“不是助手”细化为“用户明确求助时可以认真帮忙，但用团子的语气”；通常简短，复杂需求可以多说几句或澄清。天气、时间和世界动作继续经过既有工具预算、权限与结果校验。人格／Soul 是表达和成长，不是用户事实库；不要把模型猜测写进用户记忆。
- **关系许可。** 把是否允许主动提起旧事、建议、亲近表达、未来消息分别建成可撤回的选择；默认沿用既有“不催、不说教、不制造愧疚”，不因熟悉就推断获得许可。优先在当前聊天里验证自然回题与“不该提时保持沉默”，再考虑后台主动发送。
- **话题与主动续聊。** 之后才增设有来源、状态、到期时间和取消能力的事项；唤醒只进入判断与权限门，不直接发送。时区、安静时段、频率、重复消息和撤回要一并验收。跨应用连接、语音、部署和模型供应商更换留作独立评审。

## 5. 必须先说清的控制契约（提案）

| 用户操作 | 服务端效果 | 后续对话效果 |
|---|---|---|
| 更正记忆 | 新版本立即生效；旧版退役、索引同步失效；保留必要的来源与变更关系 | 旧事实不再召回；新事实只在相关且许可时使用 |
| 删除记忆 | 删除同一方面的正文与检索索引，留下无正文的阻断；失效关联 Soul 来源 | 不再以长期记忆注入；若原文仍在近期窗口，界面须说明“只删记忆”的范围 |
| 不再使用一段内容 | 来源级撤回，排除上下文和所有派生候选；并发回复发布前复核 | 即使原消息可见，也不再进入模型；源于它的旧任务不可恢复使用 |
| 删除消息／一段历史 | 使用户所选内容与其派生内容在服务端不可再用，客户端同步移除；需要明确删除范围与确认 | 历史不再展示或召回；不得由旧 SSE、任务或快照复活 |
| 不要再提 | 给猫说过的话建立边界，抑制相似回题与主动提起；用户后来主动提出时可以围绕当前请求回应 | 不再主动重复该主题；不等同于抹去整段聊天 |

实现前先核对各类来源（当前 `memory_receipts`、`boundaries`、`soul`、`async_jobs` 和后续摘要／向量）的引用图，定下“保留审计元数据但不保存可复原正文”的具体字段。更正与删除操作应在每猫串行事务中修改权威状态，向量清理可异步补偿，但检索先用权威状态过滤，不能等待索引删完才生效；正执行的轮次在发布前复核撤回版本。每一类操作的跨系统一致性和回退单独记在实施记录里。

## 6. 验收与可重复证据

按全局测试约定，以**端到端路径**为主要且优先的验证：先在隔离本机 PG／Redis 与 mock 模型上跑后端 API + worker + iOS 模拟器（或同一 API 合约的真实客户端），再经明确授权用真实模型对表达自然度做人工抽样。不要在写完代码后补孤立单测；若确需孤立测试某个系统，先列出它可能失败的所有方式，再编写代码和测试。不会以 typecheck 代替行为验收。

至少覆盖以下可观察场景：

1. 跨天累计超过 100 条消息，重启 App 后只有一个聊天框；从顶端加载直到首条，消息 ID 无重复，插入上一页时滚动位置不跳；后端仍只有一条该猫的 conversation。
2. 回复流中断、App 强退、服务端先于客户端完成、Redis 事件过期四种情况下恢复；`accepted` 前后两类重试不会重复写用户或猫消息，停止和作废语义保持原样。
3. 旧但相关的普通记忆可被适时召回；不相关、冲突、高敏感未授权、别人的猫的记忆不注入；向量服务失效时仍可正常回复，且无越权降级。
4. 用户纠错后旧偏好失效；删除记忆、来源级撤回、消息删除分别经过“新一轮回复／正在生成的回复／旧提取任务重放／重启后重建索引”检查，不会重现被撤回的事实。
5. “不要再提”只接受猫消息，拒绝后不主动回题；当前用户明确要求讨论时可以回应当前问题；世界连接更换后聊天历史与记忆保持连续，动作回执仍按新代次校验。
6. 用固定对话集人工核对团子的表达：求助时确实有帮助、纠正后接受新说法、猫咪表达自然；不虚构共同经历、不夸大动作结果、不因久未访问施压。逐项记录接受／失败例子，不把几句 mock 回复当作真实模型人格验收。

每轮端到端运行生成一个**可复验工件**：记录测试脚本版本、隔离库创建与迁移版本、mock 种子与请求序列、消息／turn／记忆状态的脱敏 JSON、关键 SSE 事件及对应断言、iOS 模拟器截图索引、通过／失败和复现命令。只把小型脱敏报告及必要示例放进仓库的实施与验收记录；原尺寸截图、密钥、token、日志和用户原文不提交。当前机器未启动 Docker，`server/.env` 不存在，本方案没有声称上述验收已通过。

## 7. 迁移、回退与评审点

- 数据库保持一猫一条 conversation；新记忆版本、索引和撤回状态采用增量迁移。先在隔离库验证旧记忆、旧阻断水位、冲突版本与没有来源的历史记录；缺来源的派生信息不能自动变成可召回事实。迁移前停旧 API／worker，确认新旧读取路径的状态门，再启服务。
- 功能分段上线：先把分页和恢复单独验收，再写更正／删除契约与权威状态，最后接语义检索；如向量索引出错，关闭相关召回并走已有有效记忆路径。任何回退仍须保留撤回阻断，不能为了兼容旧代码把已删信息重新注入。
- **本次请求评审的选择：**保留内部唯一 conversation 与 world session；第一段补齐可见历史和重启恢复；第二段先实现纠错、撤回硬门和来源治理，再提供相关性检索；第三段再放大主动能力。需特别确认的是“删除记忆”与“连来源对话也不再使用”的用户可见区别，以及消息删除应包含哪些派生对象。评审意见落地后，新增决定写入 `docs/决策/*.md` 并登记索引，再按批准的范围改代码。
