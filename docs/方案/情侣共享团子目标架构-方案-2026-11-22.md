# 情侣共享团子目标架构 · 2026-11-22

状态：Han 已批准 v4 与七项默认值；本篇为 R0 目标架构、API v2 / peer 协议草案和评测计划。R1–R9 尚未实施，现有代码仍为 Node.js + PostgreSQL + pg-boss + API v1，不把下文接口或表写成已交付。

依据：[情侣共享与整体重构决定](../决策/2026-11-22-情侣共享与整体重构.md)。本篇将批准的仓库外 v4 计划及 Bun 调查结论收为仓库内依据；运行时文字以 Han 后续决定为准：保留 TypeScript，Node 改为 Bun，better-sqlite3 改为 `bun:sqlite` + `drizzle-orm/bun-sqlite`，计算隔离称 Bun Worker 并保留验证门槛。

## 一、范围和不变的产品边界

- 一家一只团子，两名成员各有一台 Mac 和一部 iPhone；模型和领域按 N 成员设计，产品入口先开放两人。“我们仨”是群聊，“我和团子”是自己的单聊。
- 两台 Mac 为全量业务副本，两个 iPhone 的离线操作、日记、聊天、记忆、信箱及文件清单通过各自宿主完整同步；界面只展示自己的单聊及共享内容，不展示伴侣单聊。没有伴侣间的存储保密、端到端私密或独立私密副本承诺。
- 团子必须分清每人的偏好、称呼和来源；日记 `cat_allowed` 是给模型的读取许可。“别告诉 TA”是主动转告限制，不是对方无法获得数据的权限保证。
- 不托管，macOS 优先、局域网先行；transport 预留异地中继或 Tailscale 实现，R0–R9 不包含公网部署、语音实现、2D 新功能或新素材。
- 保留自研 Agent、OpenAI 兼容协议、槽位分工、来源撤回、工具预算、临时摘要与用户明确授权。不把异步任务扩成联网检索、任意代码执行等新能力。
- 七项批准值直接按决定执行：N 设计/两人开放、v2 无兼容、R1–R3 允许 main 暂不可日用且旧版留 tag、单聊不对伴侣展示、转告默认对方单聊且每人每天三条/紧急不受条数限、LAN 首版、旧数据归 Han。

## 二、每台 Mac 的组件

```text
iPhone / Mac 原生窗口
        │ 成员设备凭证，HTTPS / SSE
        ▼
 Gateway → Inbox → Router → Outbox(chat / mail / push / peer)
              │      ▲                       │ peer 行为投递
              ▼      │ worker_reports        ▼
            jobs → Workers               对方 Inbox
        │                                  （持久收据）
        └──── Store：SQLite WAL + sha256 文件仓 ────┐
                     ▲                            │
                 Replicator ⇄ transport ⇄ 对方 Replicator
                     （日志、快照、文件块，不触发行为）
```

| 组件 | 职责与边界 |
|---|---|
| Gateway | Hono HTTPS、SSE、输入校验；成员设备身份转 Actor，会话由路由寻址；不隐式绑定唯一 conversation |
| Inbox | 接收手机、peer、时钟输入；同事务写幂等 trigger、decision、ticket/job 和收据；模型和网络调用不进入写事务 |
| Router | 前台团子；普通聊天、群聊发言策略、约定、推断及汇报处理；唯一用户可见发布出口 |
| Workers | 记忆、边界、日记、托付、文件计算；保存检查点和汇报，不直接写聊天/信箱/留言 |
| Outbox | chat/mail/push 的发布副作用收据及 peer 待投递；持久化后可重试，不能把“发送成功”当成只发过一次 |
| Replicator | change_log、peer 游标、墓碑、快照引导和文件块传输；导入只更改数据，不调用 Router 或重建事项 |
| Store | SQLite 连接/迁移/仓储/事务和文件仓；唯一允许出现存储 SQL 的模块，schema 不反向引用业务模块 |

每台 Mac 一个 Bun 主进程，逻辑分工不因合并而消失。异步网络模型调用本身不需要占独立线程；CPU 密集的描述、缩略图等按需使用 Bun Worker。先验证 Worker 里的取消、崩溃回流、消息类型、资源隔离、SQLite 访问与编译后的入口定位，再决定是否完全移除 `worker_threads`，不提前承诺两者等价。

旧 API/worker 两入口不能简单 import 后视为完成单进程化：全局队列、信号处理、启动/停止、健康状态和连接生命周期需要一个统一 supervisor；退出时先停接入，再停止认领、排空/取消计算、保存状态，最后关闭存储。

## 三、从零设计的领域模型

全局业务 ID 使用 UUIDv7；UUID 的时间排序不等于因果顺序，也不作为唯一的并发冲突规则。可复制业务行带 `origin_host_id`、`hlc`；需要合并的行带 `rev`，删除用 `deleted_at` 墓碑。运行租约、凭证、文件本机可用状态等按各自生命周期存储，不机械复制。

| 领域 | 表或聚合 | 关键归属和写入规则 |
|---|---|---|
| 家庭 | households、members、hosts | 一家 N 成员、产品两人；member.home_host_id 指向自己的 Mac；host 是复制与恢复身份 |
| 设备 | devices | 合并 paired_devices 和旧 APNs devices 的设备生命周期；归 member 和 host；设备 token、推送 token、撤销有明确归属，秘密材料不进入通用共享日志 |
| 团子 | cats、cat_persona、soul_versions、yard_state | 一家一猫；个性、Soul、共享院子状态由群聊租约方单一写入 |
| 关系 | member_relations | 按成员区分熟悉度、称呼、节奏；不能把 A 的属性复制成 B 的属性 |
| 对话 | conversations、participants、messages | kind=group/direct；消息带 author_member_id，猫消息为空，modality 预留；按 HLC 加稳定并列键排序，不使用跨机全局 seq |
| 轮次 | turns | 只在发布宿主存在；关联 conversation、用户消息及输入修订；取代、取消、重答幂等、恢复语义保留 |
| 知识 | memories、memory_blocks、boundaries | subject_member_id、source_member_id、source_message_id；“别跟我提 X”针对相应成员，来源撤回可追溯 |
| 日记 | diary_entries、cat_diary | owner_member_id、原始当地日期/时区、cat_allowed、修订；猫日记与个人日记语义分开 |
| 文件 | files、file_blobs | files 放归属、说明、模型描述和引用；file_blobs 以 sha256 定位本体及本机可用状态 |
| Agent | triggers、decisions、tickets、ticket_inputs | 保留准入语义；ticket 增 conversation_id、for_member_id、publisher_host_id；trigger.source 增 peer_* |
| 执行与发布 | runs、run_steps、worker_reports、outbox、mailbox_letters | 保留代次、预算、完整检查点、结构化汇报和收据；outbox.kind 增 peer；本机执行中间状态不自动变成另机可执行任务 |
| 运行时 | jobs、chat_events、leases、model_calls、model_admissions | jobs 取代 async_jobs/pg-boss；事件按会话/轮次恢复；模型账本和准入按 host 管理 |
| 复制 | change_log、peer_cursors、peers | 每 host 自己的单调日志序号；peer 地址、指纹和协议状态；游标带 host/世代，不能混用另一宿主序号 |

删除旧的 users.host_owner、cats.user_id 单列唯一、conversations.cat_id 单列唯一、全局 messages.seq、日记专用 changeSeq/epoch 和 pg-boss 自管 schema。新的关系由 household/member/participant 表达，不在 auth 中推导唯一猫与会话。

“全量副本”指业务事实、来源和必要证明完整，不是复制所有本机运行行：turns、jobs 认领、模型并发、设备秘密和 file_blobs 本地可用位不应导致对方重复生成或误报文件已有。R1/R6 对每种表列明复制字段及本机字段，执行检查点的备份/接管不等同于复制后自动续跑。

## 四、横切契约

### 4.1 仓储、Actor 与上下文

- 业务代码只调 `store/` 仓储；SQLite JSON、`BEGIN IMMEDIATE`、`RETURNING`、冲突更新等只在存储层出现。业务事务与日志/收据原子提交，提交后总线只是低延迟提示，重启或漏提示由持久状态恢复。
- 每次请求得到 `Actor{memberId, deviceId, hostId}`；路由参数选 conversation，经 `access.can(actor, conversation)` 校验。家庭、成员、设备、peer 分开校验；“两人无隐私”不等于允许未配对设备、陌生 host 或模型读取已撤回来源。
- `context/` 统一装配所有模型输入，按“关于成员 A / 关于成员 B / 关于你们俩”分节、明确姓名和来源，不用歧义代词。记忆抽取必须输出主语；不确定先待确认，不随意归给当前说话者。
- 保留更正/撤回/回避/输入预算与摘要 guard；高层上下文选入云端的内容仍可能发给 DeepSeek。本机提取不是数据绝不出机的承诺。

### 4.2 Clock、HLC、change_log 与恢复

- 应用层 `Clock` 提供墙钟与 HLC，数据库不再调用 `now()`。测试可注入时间；租约过期与等待使用明确的时钟口径，不能混用本机墙钟、对方墙钟和消息排序时间。
- 每个 host 在同一 SQLite 提交中写业务修订及自己的 change_log；本机单调序号用于游标，HLC用于合并/展示的因果辅助，不能互相替代。
- 原创只追加事实由来源 host 负责；可变记录按 rev/写者权属合并；并发冲突、墓碑优先级和并列键在 R6 按聚合写成确定性规则和测试，不能对全部表盲用“最后时间获胜”。
- 墓碑随日志同步，清理须考虑离线 peer 的水位；快照包含一致性水位，再追增量。恢复备份后更新该 host 的世代，旧游标明确重置；手机未上传内容与待同步撤回保留，旧分享不自动复活。

### 4.3 发布宿主、leases 与 jobs

- 单聊、个人事项由成员 home host 发布；群聊、群聊事项和共享猫状态由群聊租约持有者发布。请求到另一副本时不能自行生成第二份回复，须路由到发布宿主或等待可用。
- `leases` 统一表达资源、持有 host、HLC/租期和持有者凭证；续期/交接经过 peer 协议，允许时钟漂移。HLC 和本机 SQLite 锁本身不提供跨机共识；R6 必须验证失联、睡眠、漂移、旧持有者复活时仍只有一个写者，不能仅因自己认为租约到期就双边抢占。
- `jobs` 为持久待办真相，注册 kind、认领凭证、租期、重试时刻、尝试次数与结果；事件总线只唤醒。重启扫描过期认领、核对来源/代次后恢复，不重新执行已提交副作用；预算耗尽与永久错误保留不同处理。
- Router 发布前统一检查会话新鲜度、来源修订/撤回、回避、安静时段、频率、“别告诉 TA”和发布宿主/租约。worker 汇报不能绕过出口；汇报过时可重算，不直接发布旧候选。
- 手机请求、peer 投递、时钟事件均带幂等键进入 triggers；聊天/信箱/推送/peer 副作用均有 outbox 收据。“恰好一次”指去重后的业务效果，不承诺网络恰好投递一次；允许重复传输和丢失回执后的安全重试。

### 4.4 chat_events、模型和转告

- `chat_events` 持久保存 SSE 恢复所需事件，业务终态与事件一致提交；重放按轮次内序号，事件过期从业务消息恢复快照或明确缺流。取消、可见长度、取代优先级和尾部终态补齐保留，不做纯内存 SSE。
- 只有 `llm/` 发起模型网络请求，runtime/model 管槽位、预算与准入；预算按 host 记账，群聊费用归租约方。此限制针对模型网络，不禁止 replication、天气和文件 transport 的网络调用。
- DeepSeek：chat/router/worker；本机 extract：记忆、边界、召回、日记。保留显式覆盖、自研循环、有界修正、完整 run_steps 和同槽位临时摘要，不把摘要固化成新的事实来源。
- relay 默认给对方单聊，按每人每天三条预算，紧急不受条数限；有来源署名、去重及频率收据，目标宿主复核后才开口。紧急的识别、日界归属及收据键在 R5 协议/评测中落细，不能把模型自由输出当成无限制绕过通道。
- 新代码统一多行格式、集中类型契约；schema 不反向 import Agent/世界等业务类型。

## 五、复制与 peer 行为投递：不可合并成一条链

| 通道 | 输入/输出 | 重放效果 | 成功凭据 |
|---|---|---|---|
| Replicator | 原创业务修订、墓碑、快照、文件引用/块 | 只合并数据，不触发提取、转告、生成、推送或重新入队 | 持久游标及快照水位 |
| outbox(kind=peer) → Inbox | 需要对方处理的转告、群聊发言请求等明确行为 | 同键重复返回原收据；首次才准入 trigger/decision/job | 对方事务提交后的持久收据 |

两条通道即使共享 HTTPS transport，也必须分别鉴权、版本化、观测和重试。接收方先持久化 Inbox 收据，再应答；发送方收到收据才结束投递。数据可能先于行为、行为也可能先到；来源未齐时等待复制，不能伪造来源或根据已复制 messages 自动触发行为。收据表示当次准入，不代替当前 ticket 状态。

## 六、API v2 与 peer 协议草案

以下是目标资源与最低契约，R2–R7 逐项定 DTO、状态码、限额和契约测试；R0 不宣称接口可调用。v1 整体替换，没有透明翻译或旧数据长期双写层。

### 6.1 成员设备 API

| 方法与资源 | 作用 |
|---|---|
| GET /v2/conversations | 本成员可展示的群聊与自己单聊；不以“全量复制”自动展示伴侣单聊 |
| GET /v2/conversations/:id/messages | 带来源和作者的历史分页，稳定游标；不是全局 seq |
| POST /v2/conversations/:id/messages | 幂等发送；绑定 Actor，进入对应发布宿主，返回/建立该轮 SSE |
| GET /v2/conversations/:id/turns/:turnId/stream | 从 Last-Event-ID 恢复持久 chat_events；快照与缺流语义明确 |
| POST /v2/conversations/:id/turns/:turnId/cancel | 幂等取消，带已显示长度；重答沿用独立请求键，具体资源在 R3 固化 |
| GET /v2/members | 成员与关系/称呼所需公开家庭资料 |
| /v2/files | 文件上传、清单、描述、本体获取；Range/断点续传和限额在 R7 定义 |
| GET /v2/changes?cursor= | 日记、记忆、文件清单等通用增量；返回内容、下一游标、has_more 与重置世代 |
| /v2/tickets、/v2/mailbox | 带成员/会话/发布宿主的事项与信箱，修改/已读均保留幂等和状态查询 |
| /v2/world/* | 保留院子协议，增加在场成员，会话世代按成员区分 |

成员邀请、设备配对与撤销由 identity 定义 v2 管理资源；本机 CA、短码和指纹核对继续保留。设备凭证与 peer 证书身份不是同一个角色。`/v2/changes` 为手机通用同步面，不等于 peer 可以不受约束地提交任意表变更；正文、许可和该页游标继续同次原子落盘。

### 6.2 Mac 对 Mac API

| 方法与路径 | 契约 |
|---|---|
| POST /peer/hello | 显式结对握手、确认家庭/host/协议版本与证书指纹，不接受任意邻居自动入家 |
| GET /peer/changes?cursor= | 按来源 host/世代拉取日志；支持快照后追增量，不触发行为 |
| GET /peer/blobs/:sha256 | 按内容哈希拉本体，支持 Range；校验完整哈希后才标本机已有 |
| POST /peer/inbox | 接收带来源/目标/幂等键的行为投递，同事务返回持久收据 |
| POST /peer/lease | 群聊发布租约的续期与交接，拒绝旧持有凭证 |

peer 使用局域网 mTLS 加证书指纹固定；手机链路保留设备凭证与本机 CA 信任，不把 peer 权限发给手机。transport 封装手机↔宿主与宿主↔宿主寻址/传输。各协议带 `protocol_version`；两 Mac 版本不一致时仅在可解析的只读同步范围工作并提示升级，不投递新行为或交接写租约；不能声称任意未来 schema 都能读取。

## 八、Bun 的已知证据与打包约束

2026-11-22 调查在 Linux x64 隔离副本、独立 PG17、mock 模型执行；Bun 1.4.5、Node 22.23.5、Vitest 5.0.0。以下为调查证据，不是本篇 R0 新跑的端到端验收，也不证明 SQLite 重写已通过。

| 探针 | 实际结果与边界 |
|---|---|
| bun install | 从 pnpm-lock.yaml 迁移锁文件，108 包安装成功；当前仓库依赖/锁文件尚未切换 |
| 现有 PG 后端 | bun src/api.ts 与 src/worker.ts 启动；HTTP 与 CA 验证的 HTTPS healthz 均 ok/db=true；postgres.js LISTEN/NOTIFY 收到通知 |
| 同库重建后的对照测试 | Node 与 bunx --bun vitest 各 48 文件、506 测试通过；83.87s / 50.70s 为单次运行，不作性能承诺 |
| 独立编译入口 | API/worker 的 bun-linux-x64、bun-darwin-arm64 均编译成功；Linux 各约 107M，Darwin API 88M / worker 87M |
| Linux 可执行文件 | 源目录外启动、HTTP/HTTPS 成功；编译后的合并入口完成 mock 鉴权聊天/SSE accepted 与 done |
| SQLite 小探针 | bun:sqlite + drizzle-orm/bun-sqlite 的建表、WAL、insert RETURNING、select 成功，不代表 PG schema 可直接移植 |

必须在 R1/R8 的打包验收中覆盖：

1. 合并入口**先导入 `reflect-metadata`**。只有依次动态 import api/worker 的合并二进制曾报 `tsyringe requires a reflect polyfill`；前置导入后 Linux 启动成功。后续 supervisor 不依赖偶然模块求值顺序。
2. `bun build --compile` 不自动收齐文件系统资源。现有 migrate.ts 单独编译曾报 `Can't find meta/_journal.json file`；加 `--asset=drizzle` 后在新库迁移成功。SQLite 迁移目录同样显式用 `--asset` 嵌入并验证路径，或明确随包交付，不能依赖源码 cwd。
3. 原有生产入口未暴露外部 `.node` 扩展要求；better-sqlite3 不进入新依赖，Bun 内建 SQLite 是目标。测试/构建依赖中的原生扩展不代表业务二进制已覆盖所有平台；动态 import、Bun Worker 入口、文件资源须在成品中逐项验证。
4. Linux 成品仍动态链接 libc/libpthread/libdl/libm，不称“完全静态”。Darwin arm64 成品约 87–88M，但**macOS 二进制尚未运行**；签名、公证、系统版本、TLS/钥匙串、休眠恢复和宿主更新均留给 macOS 验收。
5. 密钥、CA 私钥、配对凭证、SQLite 和文件本体保存在外部可写数据目录，不编译进二进制。备份使用一致性在线备份方式，不直接拷贝一个正在写 WAL 的主文件；恢复前停认领/发布、备份当前状态，失败回退并更新 host 世代。

## 九、旧数据与扩展边界

`cattt import-pg` 只做一次性搬迁：Han 为首成员，旧对话归 Han 单聊，旧记忆主语/来源和日记归属标 Han，托付、约定、信箱与历史证明保留。逐表比较行数、关键字段哈希并抽查聊天、召回和日记读取，不通过不切换；旧 PG 目录删除前另行确认。历史执行不可因导入重新发送旧通知。

旧 iOS 本地日记首次连接 v2 后按新身份对齐/上传，保留未上传与撤回，不将原本地模拟空间自动归给远端成员。升级旧版时不提供 v1 兼容网关；留存旧版 tag 和备份用于回退，不把新写入直接反向塞回旧 schema。

预留但不在本轮实现：异地 transport；messages.modality + files 附件/转写进入同一 Router 的语音；N 成员扩展；新 Mac 从伴侣完整业务副本快照恢复；新增 jobs.kind 经 worker_reports 回流而不改 Router 发布出口。
