## 范围

陪伴为主，worker 结构化汇报、API 统一发布。仅改后端与文档，不加联网、外部文档、代码执行或 UI 能力。

1. 按需提供 search_chat_history 与 read_chat_history：宿主绑定猫、会话和本轮上界，查询本轮之前的已许可持久原话（也覆盖预算裁剪掉的近期消息）。中文按字面匹配，SQL 参数化；许可、撤回、边界和派生来源过滤先于结果限制。搜索最多5条、展开最多6条，附来源、角色、序号、当地日期、时区与截断标记。关闭 useMemories 禁用；learnMemories 不影响已许可读取。历史只作资料，事实更正以最新为准。
2. 前台与后台共享请求预算助手：估算指令、消息、工具 schema 和输出预留；不是供应商精确 token 数。首步和后续步骤均检查，只在请求副本删除旧完整对话或工具轮次；保留当前问题、人格、边界和必要工具配对。必要内容超限明确失败，不截断当前问题、不修改持久历史、不额外调用模型。
3. 动态读取来源在送入模型前写入 turns.contextSourceIds 或 runs.report.dependencies.messages；沿用已有锁、事务、版本和出版复核，维持 commitOutcome 与检查点语义。

## 测试顺序

先写集成测试，在旧实现证明失败，再实现。断言真实传入 mock model 的请求：30条之外中文搜索展开、前台和 worker 工具循环、跨账号和未来消息隔离、许可关闭与学习关闭、撤回与边界、派生回复和日记来源、SQL 通配符字面、空结果与查询上限。来源登记后撤回必须使派生回复失效，模型前许可变化不得泄漏。

预算覆盖中文、emoji、混合长文本、巨大历史和工具输出、首步和后续步、当前问题原样、工具配对、输入不变及不可压缩失败；后台恢复不得重复执行 report。

仅使用新隔离 PG/Redis，运行完整后端测试、pnpm typecheck 和 sh tools/check_all.sh。不得迁移、清空现有数据库或停止用户服务。验收区分 mock、真实模型和部署；本轮不调用付费真实模型。
