# 本地优先架构重塑 · 方案 · 2026-11-19

状态：**已批准**，评审点按推荐值（见[决策](../决策/2026-11-19-本地优先.md#方案批准)）。依据 [2026-11-19 本地优先](../决策/2026-11-19-本地优先.md)。参考了 [linger](https://github.com/simplexai-labs/linger) 的本地安装、单模型调度与记忆评测；linger 为改版 Apache-2.0，本地自运行不触发其“托管服务”条款，但本方案只借设计，不复制代码与前端素材。

F 批状态：macOS 宿主、菜单、打包与备份恢复已实施并通过本机烟测；原云部署目录与镜像交付脚本已移除，开发数据库 Compose 保留。本机验收改由 [宿主脚本](../../desktop/macos/README.md) 覆盖；成功配对链路待 E 批服务端合入，未公证、未验证真实退出登录后的自动启动。以下现状表保留方案批准时的基线。

## 1. 现状与冲突

| 方面 | 现在 | 与本地优先的冲突 |
|---|---|---|
| 后端位置 | API + worker 在本机开发能跑（`server/`），部署包按云准备（`server/deploy/`） | 云部署包不再是目标 |
| 模型 | 只有 DeepSeek 云 API 与 mock（`server/src/config.ts`、`server/src/runtime/model.ts`） | 没有本地模型，也没有“自带 key”的选择 |
| 数据与队列 | PostgreSQL + pg-boss 为唯一真相；Redis 只做聊天事件流、会话锁、取消与可见长度（`server/src/turns/events.ts`） | Redis 是一个额外要打包、要托管的进程 |
| 模型并发 | 每类后台任务固定并发，每日调用/token 预算 | 本地只有一个模型时，后台任务会挤占聊天 |
| 手机连接 | Release 只接受配置好的 HTTPS 地址；Debug 可填 `localhost`（只对模拟器有效）（`ios/Maomao/Backend/Backend.swift`） | 没有手机与电脑的配对和发现 |
| 身份 | Sign in with Apple + 服务端会话（`server/src/identity/service.ts`） | 本地单主人场景下 Apple 登录不是必需的 |
| 推送 | 服务端持 APNs p8 密钥直发（`server/src/push/`） | 不能把开发者的 p8 分发到每台用户电脑 |
| 电脑在线 | 默认服务一直在线 | 电脑会睡眠、关机、离开家 |

## 2. 目标形态

```
iPhone App ──(配对后的 HTTPS：局域网 / 远程通道)──▶ 电脑端宿主
                                                   ├─ API（聊天、SSE、唯一出口）
                                                   ├─ worker（托付、记忆、日记）
                                                   ├─ PostgreSQL（私有数据目录，只绑回环）
                                                   └─ 模型来源：本地推理 ｜ 自带 key 的云 API（可选）
```

保留不变：PG 唯一真相、pg-boss 投递、事项与执行分离、检查点续办、发布前复核、安静时段、每日预算。

## 4. 评审点（附推荐）

1. **推送。** 推荐：先不做远程推送；手机在拿到约定时间时排本机通知，打开 App 时拉取信箱。远程推送需要开发者持有的 APNs 中继，会重新引入我们运营的服务，另行决策。
2. **远程访问。** 推荐：先只支持局域网；不在家时显示“团子在家里的电脑上”。之后再在 Tailscale 一类用户自管的 VPN 与自建中继之间选。
3. **平台。** 推荐：电脑端先只做 macOS（与 iOS 用户重合、团队熟悉），Windows/Linux 后续。
4. **数据库。** 推荐：保留 PostgreSQL，随宿主打包（私有数据目录、只绑回环、初始化成功再改名），不换 SQLite（换就要换掉 pg-boss 并重证恢复语义）。
5. **默认模型来源。** 推荐：安装时按硬件推荐本地模型；硬件不够时引导填自带的 DeepSeek key。不再内置任何开发者 key。
6. **`server/deploy/`。** 推荐：F 批落地时删除云 staging 部分（`compose.staging.yml`、`Caddyfile`、`rollback.sh` 中的云路径），本机验收部分并入宿主测试。

## 5. 不做

多租户托管、Apple 后台与云备案流程、Codex/Claude 原生会话编排、多 Agent 拓扑、邮件/日历接入。
