## 设计

公共模型目录 `server/src/llm/`，业务代码只依赖这里：

1. **消息类型**：`system / user / assistant / tool` 四种角色；assistant 内容可含 `text`、`reasoning`、`tool-call {toolCallId, toolName, input}`，tool 内容是 `tool-result {toolCallId, toolName, output: {type:'json', value}}`。与现有检查点里存的结构一致，不迁移数据。
2. **`ModelClient` 接口**：`stream(request)` 返回事件流（`text-delta`、`reasoning-delta`、`tool-call`、`finish {finishReason, usage}`）。请求含 system、messages、tools（JSON Schema）、`toolChoice: auto | none | required`、`maxOutputTokens`、可选 JSON 输出格式、额外请求字段（思考开关）、`AbortSignal`。
3. **OpenAI 兼容客户端**：基于 `fetch` 的 `/chat/completions` 流式实现，自己解析 SSE、拼接分片的 tool_calls、读取 `stream_options.include_usage` 用量。DeepSeek 复用同一实现：base URL 换成 DeepSeek，思考开关写 `thinking: {type}`；思考模式下工具循环把 `reasoning_content` 带回下一步。
4. **错误**：`ModelHttpError(statusCode)`、`ModelAuthError`（未配置 key）两类；`classifyModelError` 与托付的 `errandRetryable` 改认这两类，判定规则不变（402 额度、401/403 鉴权、400/422 请求错、408/429/5xx 与网络错误可重试）。
5. **一次性调用**：`generateText(client, request)` 与 `generateObject(client, request, zodSchema)`：后者请求 JSON 输出（兼容来源用 `json_schema`，DeepSeek 用 `json_object` 并把 schema 写进系统提示），解析后用 zod 校验；`maxRetries` 只重试可重试错误。
6. **包装器**：准入与预算使用包住 `ModelClient.stream` 的装饰器，语义不变（预算按请求字节 + 输出上限预留，流结束或出错时结算；准入在流结束、出错或取消时释放）。
7. **Agent 循环**（`llm/loop.ts`）：显式 `for` 循环，每步：复核 guard → 决定是否终答步 → 上下文裁剪 → 流式请求 → 按现有规则发布文字（终答步直接发布；auto 步确认没有工具调用后才发布）→ 顺序执行工具（工具预算、改变世界的工具一次、持久记录先于副作用）→ 追加 assistant 与 tool 消息 → `onStep`。没有工具调用即结束。前台聊天与后台托付共用同一个单步函数，托付仍然每步落检查点。
8. **上下文管理**：`input-budget.ts` 改用自己的消息类型，裁剪规则不变（先删完整旧用户轮次，再删最早的完整工具链，当前用户及其后工具链保留）。
9. **mock 与测试**：`runtime/mock.ts` 改成实现 `ModelClient` 的假模型，行为逐条保持；测试使用 `scriptedClient`（按步给事件），DeepSeek DSML 等回归用假 `fetch` 测真实客户端。
