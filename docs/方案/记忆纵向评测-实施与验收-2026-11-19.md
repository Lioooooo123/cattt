# 记忆纵向评测与检索融合

状态：批次 J 已实现本机评测和排序调优，未部署；以下为 mock 扩词、真实 PostgreSQL / Redis 的结果，不代表真实模型说话质量。

## 样例和计分

`server/test/memory-eval.test.ts` 有 11 条独立猫的时间线、35 个探针、52 个 `mustInclude`。原话按第 N 天保存，候选写入和再次确认走 `applyCandidate`，更正、遗忘、撤回和开关使用现有控制函数；仅原话、账号、边界和确认时间夹具直接写库。包括 65 条近期无关记忆、少字面的更正值、仅扩词命中、敏感内容的直接/间接请求、禁止重提、关闭后重新打开、扩词异常。

新增 5 个容量竞争探针，每个有 12 个合格的相关候选、8 个期望值：近期饮品习惯对旧菜单、长期偏好再次确认对较近但未再确认的旧茶店、更正后的简短偏好对多词面的随手见闻、仅扩词命中的科幻偏好对弱词面命中的旧目录，以及长段点单说明对重复冗长的旧店介绍。字符竞争中 8 个期望条目整体能放进 2400 字符，旧介绍若抢先会挤掉多数期望值；所有竞争探针额外断言 8 条与 2400 字符上限。旁支相关但次要的旧内容算精确率损失，不伪装成越权；已更正的原值仍放进 `mustNotInclude`。

普通探针走 `recallPermissions` + `recallMemories`，空记忆、扩词故障、关闭使用走 `buildTurnContext`。约定探针走 `scheduleFollowup` → `scanFollowups` → `processFollowup` → publisher，验证 23 点不发、次日 08:59:59 不发、09 点发一次、重复扫描与重放不再发。

计分用完整记忆值：召回准确率 = 命中的 `mustInclude` / 全部 `mustInclude`；精确率 = 命中的 `mustInclude` / 所有召回值。违规为命中 `mustNotInclude` 的数量加超额主动消息数。没有正例的格记为「—」，不是 100%。09 点该发未发计为准确率下降。断言违规为 0、准确率不低于最终实测的 52/52（100%），而不是把阈值降低到基线。

## 排序决定

除了上述本地饮品同义词补充，入选条件不变：敏感记忆必须明确保存且直接命中；明确的表达偏好可入选；无关内容不能因新近确认入选。对合格候选分别计算 IDF 词面命中、扩词命中、确认时间指数衰减的名次，以 `1 / (60 + rank)` 融合。相同分数共用名次，避免数组顺序污染排名。分词可能漏掉查询中的完整主题词（如「拿铁」），该词仍可用于准入，但已在查询正文中的原词不再投扩词票，避免多词面的旧内容获得双重奖励。

时间分数为 `exp(-ln(2) * ageDays / 90)`，`ageDays` 按 UTC 日边界计算：同日确认共享名次，不因相邻写入的毫秒差把同批更正拆成不同新鲜度。三个月为偏好再确认的保守时间尺度，不设置过期淘汰。由于标准 RRF 仅使用名次，半衰期的具体值并不改变时间榜的单调次序；不能声称这次验证了 90 天优于其他半衰期。后续若要校准时间影响强弱，需要独立留出集和时间榜权重实验。

`selectMemories` 先确定每个指纹最新修订（同修订取最新确认），再按融合顺序和完整条目预算选取，避免旧值多字面命中先占去重名额。新增 6 项单测验证近期优先、同日时间并列、三路融合、原词不重复计票、饮水同义词及敏感门不被绕过、旧修订高分仍被更正值替代；原有相关性测试未修改。

## 运行与边界

先按 `server/.env.example` 启动 Docker Compose，在独立的全新 `maomao_test` 库迁移；不使用开发库。命令前设置：

```sh
export DATABASE_URL=postgres://maomao:maomao@localhost:5432/maomao_test
export REDIS_URL=redis://localhost:6379/1
export MODEL_PROVIDER=mock
pnpm --dir server db:migrate
pnpm --dir server eval:memory
```

本机验证结果：全新测试库迁移成功；`test/memory-*.test.ts` 共 8 文件、68/68 通过（包括评测）；`test/followup.test.ts` 14/14 通过；`pnpm --dir server typecheck`、`python3 tools/repo_check.py`、`git diff --check` 退出码均为 0。首次新增融合单测混用了内置咖啡主题扩词，预期不成立；改为隔离的词项测试三路融合后通过，原有测试没有放宽。

限制：

- 「不该说」目前只检查提供给模型的长期记忆，不检查模型实际生成的回复，也不把仍允许的近期聊天原话算成记忆召回。因此不构成遗忘后生成文本绝不复述的证明。
- 现有 `buildTurnContext` 对没记过、关闭使用、扩词不可用都返回空 `memoryIds`，没有可区分的记忆状态字段。本批分别驱动这三种状态、验证不猜测提示和不开关绕行，但尚不能断言模型会说「没记过」还是「暂不可用」；要覆盖措辞，需要后续明确上下文状态契约和回复级评测。
- 免打扰与重复汇报用约定的真实 publisher 路径覆盖；未另建 errand worker report、后台主动推断和 APNs 端到端样例。它们的既有专用测试不算入本评测分数。
- 当前没有人工留出集、模型语义能力评分或大规模真实用户分布评测，不能将开发集上的改进解释为检索效果普遍提升。
