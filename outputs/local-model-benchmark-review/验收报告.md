# macOS 本地模型档位实测 · 2026-11-19

状态：**已完成本机虚拟机基准与模型清理**。宿主引导文字换行、缺 Ollama 时重复按钮已修正（`0df4e9f`）；窗口本轮未做视觉复验。实体 Mac、长期质量、并发聊天与完整 App 链路不在本次结论范围。

## 环境与方法

- Apple M4 Pro **(Virtual)**，`VirtualMac2,1`，12 核、16 GiB；macOS 26.6.2 / 25G83；Ollama 0.40.16，`127.0.0.1:11434`。Metal 日志是 **Apple Paravirtual device**，不是实体 M4 Pro GPU 跑分。开始可用磁盘约 24 GiB，7b 已有缓存；模型 ID：3b `357c53fb659c`、7b `845dbda0ea48`、14b `7cdf5a0187d5`。
- 原命令 `pnpm --dir server model:setup … --env-file /tmp/bench-<tag>.env` 在本机 pnpm 11.11.0 被自身环境文件参数截获，退出 9，提示 `/tmp/bench-qwen2.5:3b.env: not found`，未执行 setup。使用下面的显式 `run` 与参数分隔符后正常；未修改服务端代码或 pnpm 配置。

```sh
pnpm --dir server run model:setup -- --json --yes --model qwen2.5:3b --env-file /tmp/bench-qwen2.5:3b.env
# 同样替换为 qwen2.5:7b、qwen2.5:14b
ollama run qwen2.5:3b --verbose '团子，我今天有点累。请像温柔的猫一样陪我坐一会儿，只用一句不超过20个汉字的中文回应。'
```

- 首轮 CLI 使未缓存的 3b、14b 自动下载；首次下载耗时取服务日志的 `/api/pull`。纠正命令后另做统一顺序的正式轮（00:22–00:31）：每档 setup → 卸载该档 → 三次独立 CLI，之后卸载前一档再换档。采样确认正式轮没有两档同时驻留；下表均取正式轮，不混用较快的预跑结果。
- 三次 CLI 第一次为进程冷加载（权重已缓存，不清 OS 文件缓存），后两次保持驻留、允许提示缓存；默认采样参数，没有锁随机种子。TTFT 是启动 CLI 到首个非空 stdout 字节，含 CLI、加载与预填充，不是纯服务端 TTFT。速率是 `--verbose` 原值，短输出仅 7–14 tokens，不能视为稳定长输出吞吐；暖运行有提示缓存，不能用其 prefill 值作跨档比较。
- 每约 2 秒采样 `/api/ps`（即 `ollama ps` 数据源）、daemon + `llama-server` + CLI 的 RSS、`vm_stat`、`sysctl vm.swapusage`。系统未重启、未清 swap，其他应用保持原状；采样峰值不是精确瞬时峰值。

## 内存与 GPU

| 模型 | 进程合计 RSS 采样峰值 | `ollama ps` size 峰值 | 全系统压缩器占用峰值 | swap 使用起→止，MiB | 新增 swapout 页（16 KiB/页） | 日志 GPU offload |
|---|---:|---:|---:|---:|---:|---|
| 3b | 3.93 GiB | 164.0 MiB | 0.17 GiB | 2002.19 → 1976.56 | 0 | 37/37 层 |
| 7b | 8.87 GiB | 259.0 MiB | 0.18 GiB | 1976.44 → 1932.69 | 0 | 29/29 层 |
| 14b | 11.60 GiB | 818.0 MiB | 8.07 GiB | 1932.38 → 2034.75 | 53,672（约 0.82 GiB） | 49/49 层 |

14b **没有加载失败或 OOM**，但该区间观察到新增 swapout 及 47,055 页 swapin（约 0.72 GiB）；预跑时系统 swap 曾从 0 增至约 2009 MiB。正式轮 3b/7b 的约 2 GiB swap 是前轮遗留，不是本档新增写出。系统指标并非仅模型占用。

日志原句为 `load_tensors: offloaded 37/37`、`29/29`、`49/49 layers to GPU`，`ollama ps` 报 100% GPU。但同一日志还有 `CPU_REPACK model buffer size` 1833.90 / 4166.82 / 8145.18 MiB；`ps size` 明显不能代表完整模型内存，不能以 164–818 MiB 宣称模型只占这些内存，也不能把“全层 offload”当成实体 GPU 性能保证。

## 结论、验证与清理

- **16 GB→7b 的容量和功能探针成立，但在这台 VM 上不宜当作流畅交互推荐。** 正式轮 3b 平均 2.58 tok/s、7b 0.80、14b 0.48；本 VM 优先试 3b，7b 是需要用户接受明显等待的可用档。14b 虽能运行，但压缩、swap 与延迟不支持提升推荐。不能从单台 VM 推翻实体 16 GB Mac 的档位表，本次不修改推荐代码；实体机器仍需复测，完整中文陪伴质量仍未评测。
- A 部分 `swift build`：`Build complete! (1.95s)`；`swift test`：`Executed 14 tests, with 1 test skipped and 0 failures`（实际 bundle 连接失败集成测试需环境变量，本轮未重复）；提交钩子“跨端一致性检查通过”。本轮未打开窗口做视觉复验。
- 已执行 `ollama rm qwen2.5:3b`、`ollama rm qwen2.5:14b`，均返回 `deleted`；`ollama list` 只剩 **qwen2.5:7b / 845dbda0ea48 / 4.7 GB**。未重启 Ollama，清理后 `/api/version` 仍返回 `0.40.16`。
- 原始命令、带时间的事件、九次正式 CLI 输出、2 秒内存样本与服务日志保存在本机持久目录 `~/cattt-local-model-benchmark/validated-run/`；首次下载日志及未纳入正式表的预跑记录在其父目录，未将原始大日志加入 Git。
