## 修复与边界

`worker/memory.ts` 不再把空提取或候选未被接受时的 clarification 单独作为可信的保存结果。未保存时始终先给出“本次没有保存记忆，不能说已经记住或改好”，澄清内容保留但标为非凭证并引用。回归覆盖普通澄清、事实复述、虚假成功措辞、空输出、候选未写入和非法结构；已有正常保存场景继续覆盖。

尝试过补充提取提示和完整输出示例：可产生记忆行，但仍出现否定含义丢失等质量问题，因此撤回提示词实验，只保留上述确定性结果修复。这个修复不保证小模型的自然语言理解，也不保证聊天模型永远服从提示。建议使用能力更强的本机提取模型后重做语义验收；本次未扩大下载或性能评测范围。

未执行 iOS、视觉、独立网络服务、推送或完整后台发布验收。没有使用依赖 macOS 模拟器、且自行清除环境密钥的旧 `test_real_model_e2e.py`。

## 切换前后对照：每版 5 次

按追加要求，在两个独立 detached worktree 中分别安装锁定依赖，运行当前主分支 `4899fe7` 与切换前 `9290130` 的正式 `extractSource`；再在修复分支运行 5 次。均使用同一 Ollama 模型、本机 `maomao_test` PG 和环境：来源 openai-compatible、extract thinking=disabled、本机并发 1。不调用 DeepSeek。

每次新建隔离的合成账号/猫/会话，已有记忆为空、无上一条猫消息，原话严格为 `记住，我不喝咖啡`（无句号），消息日期固定为 `2026-11-19T04:00:00Z`，以 foreground=true 调用提取。每次检查返回结果和实际 memories 行，然后删除该合成账号；不会因 receipt 或已有记忆跳过模型。总计 15 次实际请求，各次无提取异常，也没有重试。

成功标准：实际保存来源正确、语义保留“不喝咖啡”的记忆，不能仅以 JSON 解析成功计数。

| 版本 | 正确保存 | 有任何记忆行 | 提取/结构解析无异常 |
| --- | --- | --- | --- |
| 切换前 `9290130` | **0/5** | 0/5 | 5/5 |
| 当前 main `4899fe7` | **0/5** | 0/5 | 5/5 |
| smoke 分支 schema 修复后 | **0/5** | 0/5 | 5/5 |

因此，**本输入未观察到切换造成的提取成功率回归**：旧实现同样不能保存。这个小样本不排除其它输入上的回归，也不能据此宣称模型质量合格。此前仅凭新实现的失败归因于小模型，证据不足；现补上旧实现的实测对照。

### 实际请求体对照

在导入模型模块前安装仅观察、不修改响应的 fetch 包装器，只记录 `/chat/completions` 的 JSON body，未记录任何 header。每个版本内 5 份 body 完全相同。两个基线的整个 `messages` 数组逐字一致，包含相同系统提示、日期、空记忆块及用户原话；其排序键 JSON 的 SHA-256 为 `2897c01da5be4ea859e013ea92290f389abdd03da592d6cef51d280cef9b7920`。

| 字段 | 切换前 | main（修复前） | 修复后 |
| --- | --- | --- | --- |
| model | qwen2.5:0.5b | 相同 | 相同 |
| 系统提示、messages | 相同 | 相同 | 相同 |
| temperature / top_p | 均不发送，使用服务默认值 | 相同 | 相同 |
| max_tokens | 2048 | 2048 | 2048 |
| reasoning_effort | none | none | none |
| response_format.type | json_schema | json_schema | json_schema |
| json_schema.strict / name | true / response | 相同 | 相同 |
| schema 方言 | draft-07 | **2020-12** | draft-07 |
| 根 required | `["memories"]` | **`["clarification","memories"]`** | `["memories"]` |
| memories.items.required | subject、predicate、value、confidence、sensitivity | **还额外要求 kind、explicit、correction、usesQuestion** | 与旧版相同 |
| stream / stream_options | 不发送（旧 generateText 为非流式请求） | true / include_usage=true | 保留自研流式协议 |

修复前后都发送了完整 schema，未发现缺 schema、少输出额度、temperature、strict 或 name 不一致。真实差异是自研转换默认使用 Zod 的**输出语义**，将本应由本地解析补齐的 default 字段也设为必填；旧转换使用 draft-07 的**输入语义**。已修复 `llm/schema.ts`：draft-07、io=input、复用定义内联，并保持嵌套对象 additionalProperties=false，同时保留字典的附加值 schema。显式传入的 JSON Schema 不改写。

修复后的实际 `response_format` 与旧版逐字段完全一致；整个 body 唯一剩余差异为自研协议的 `stream:true` 与 `stream_options:{include_usage:true}`。5 次复验仍未写入记忆，不能声称 schema 修复提高了本例的质量，也不能仅凭这些样本认定 streaming 与非 streaming 等价。默认采样未固定 seed，不能把不同的错误措辞当作单字段因果证据。

回归新增默认字段可选且本地补默认值、嵌套对象、字典 schema、空对象及显式 JSON Schema 不改写测试。两个临时 worktree 均已移除。
